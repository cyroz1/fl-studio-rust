# Rust DAW compatibility rebuild

## Parity progress — 2026-10-09

**Early prototype; not yet suitable as a full FL Studio replacement.** The [parity roadmap](docs/parity-roadmap.md) is an unweighted checklist: partial items cover only their stated subsets, and a completed small item does not count as the same amount of work as a complete subsystem.

- **Working foundations:** lossless FLP parsing and round-trip writing, selected project and note edits, MIDI import and partial export, and cross-platform CI packaging.
- **Partial runtime and editing:** early Playlist, Channel Rack, Piano roll, Mixer, plug-in, and audio views; Windows shared and exclusive audio; playback and a first combined WAV render for supported audio clips, Sampler notes, and mapped installed VST3 instruments.
- **Major parity gaps:** complete song rendering through automation, Mixer routing/effects, and PDC; automation playback; broad VST compatibility and state write-back; full FL Studio window/control behavior; and verified compatibility across FL Studio versions.

See the roadmap for subsystem-level status and evidence.

This is a clean-room Rust project started from the FL Studio 26.1.6.5639 installation supplied with the workspace. It is an independent rebuild; it does not load, patch, or link against the installed FL Studio executable or engine. The end goal is to open and modify any FL Studio project with backwards compatibility, matching controls, windows, and editing behavior, installed plug-in hosting, playback, and rendering. The current code contains the lossless file-format core and the first desktop editing shell; it is still far from full parity.

The first milestone is deliberately a compatibility foundation: inspect FL Studio project (`.flp`) files and preserve every event, including data the reader does not understand. The reader identifies common `.fst` header variants for channel, native plug-in, VST generator/effect, and Mixer insert states; plugin payloads are still opaque. FL Studio's own documentation describes `.flp` as its native project format, `.fst` as a state/preset format, and ZIP project packages as projects bundled with referenced sample files. The installed projects and presets provide a local compatibility corpus.

The desktop app also opens standard `.zip` project packages, extracts their regular files to a temporary workspace for relative sample lookup, and writes edited FLP data back while retaining the other files. Saving a plain `.flp` as `.zip` currently creates a project-only archive; collecting referenced samples is still outstanding.

## Current milestone

`flp-rebuild` can read the FLP chunk envelope and event stream, report header information, event counts, channel summaries, and a small set of project fields, and write a lossless round-trip copy. `preset-info` classifies known FST state-file variants and reports their decoded structure. Launch the native desktop shell with `cargo run --release --bin fl-studio-rebuild`. It uses the bundled Inter UI font under SIL OFL 1.1 (license included in `assets/fonts/Inter-OFL.txt`) and eframe's WGPU renderer, opens maximized, can open/save FLP files, and displays the decoded Playlist, Channel Rack, Piano roll, Mixer, Plug-ins, and Audio views. F5, F6, F7, and F9 switch between Playlist, Channel Rack, Piano roll, and Mixer, respectively. The Audio view selects input/output devices and provides a live capture meter, input monitoring, a quiet output test tone, and direct input recording to WAV. Recording adds a sample-backed Audio Clip at the Playlist playhead on the first non-overlapping lane; it requires an existing Audio Clip in that arrangement as a verified record template and does not include Mixer routing or effects. Windows offers WASAPI shared and exclusive access; shared mode uses the Windows audio engine, while exclusive mode opens the selected endpoint directly and reports unsupported formats or access conflicts. The Playlist supports selecting, editing, and duplicating clips; its clip data inspector also exposes the raw item index, track index, group, flags, offsets, and decoded scale field. The Channel Rack's pattern/bar selector and sixteenth-note step grid can add or remove notes at key 60. **Graph editor (Ctrl/Cmd+K)** exposes per-step note key, velocity, pan, release, fine pitch, modulation X/Y, and shift; click-drag bars to edit values or create a C5 note on an empty step, and right-drag to interpolate values across steps. The Piano roll supports choosing a pattern and channel, double-clicking the grid to create a note, and editing note start, length, key, and velocity. Its Draw (P), Paint (B), Select (E), Zoom (Z), and Playback (Y) tools include box and modifier selection, region zoom, background-click zoom out, cursor-centered Page Up/Down zoom, and note audition while clicking or dragging; Quantize can target a channel or the selected notes; selected groups can be moved, resized, or deleted together. An independent zoom slider is also provided. Its advanced note properties editor also exposes raw flags/group, fine pitch, release, stored MIDI channel, pan, and modulation X/Y fields. Drag a note body to move it on the grid; drag its right edge to resize it. The snap menu offers no snap, subdivisions of a beat, one or two beats, and a bar sized to the project's time signature. Dragging vertically changes the key within the visible keyboard range. These note operations rewrite only the affected length-prefixed score event and preserve other event bytes. Tempo edits are also written into the loaded project. The Plug-ins tab scans conventional VST locations on Windows, macOS, and Linux, plus directories listed in `VST3_PATH` and `VST2_PATH`. On project open, recognized VST3 channels are matched to installed bundles by wrapper-reported plug-in or bundle name and loaded into the process; marker-12 state maps nested record 3 to the VST3 component stream and record 4 to its controller stream. The loaded instance is linked to its Channel Rack row for playback, and its native editor can be opened on request. Unsupported state layouts and missing or failed plug-ins are reported; process isolation and state write-back remain incomplete. The Plug-ins view can also load additional VST3 instances and expose host-reported parameters. Mixer inserts show editable raw fader and pan candidates when each has a unique zero-scope `0xE1` record matched by the corpus-derived target convention; native track numbering, meters, effect slots, and routing are still incomplete.

The desktop shell's **Undo**/**Redo** buttons and Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z shortcuts restore lossless FLP document snapshots across editors. History storage is capped at 64 MiB; undoing plug-in-host state and non-project UI state is not included.

The File menu keeps up to 50 recent projects across launches, shows the first ten with a **More** submenu, and opens the first ten with Alt/Option+1–0. It also offers autosave intervals of 5, 10, or 15 minutes (or Never). Regular modes pause during playback; Frequent mode saves every five minutes during playback and before plug-in loads, while Very frequent mode saves every minute and before plug-in loads. It keeps a configurable shared set of backups in the user data folder. Manual saves preserve the previous project, and a newer autosave prompts for recovery when a project opens. **Backup now**, **Revert to last autosave**, and numbered **Save new version** (Ctrl/Cmd+N) are also available. Opening another project or using File > Exit or the window close button with unsaved edits prompts to Save, Don't Save, or Cancel. Autosave requires a named project.

In the Piano roll, enable **Paint mode** and drag across empty grid cells to create snap-length notes. Double-click note creation remains available with Paint mode off.

Resolved audio-channel clips show an asynchronously decoded combined waveform in the Playlist. It follows horizontal zoom and clip source offsets. Stereo or spectral previews, fades, and gain envelopes are not shown yet.

The Browser now navigates local folders, filters samples/projects/presets/MIDI, opens FLP projects, and queues MIDI files for import. Double-clicking an `.fst` preset or choosing **Inspect preset…** opens read-only details parsed from its lossless document, including preset kind, header format, version, and event/state counts. Expandable sections show decoded channel identities and paths, recognized plug-in state metadata, Mixer insert fields, and automation point counts; raw plug-in state remains opaque and applying it to a live channel is not implemented. Right-clicking audio in Files or Favorites offers **Send to [channel]** for the selected sample-bearing Channel Rack row and updates its existing sample-path event. Audio files can also be dragged from Files onto a compatible existing sample-bearing Channel Rack row to replace its sample, or onto the Channel Rack add area to create a new Sampler channel. In Files and Favorites, Shift+Up/Down sends the previous/next visible audio file to the selected sample channel when no text field has keyboard focus. Sending samples to plug-ins and dragging samples to the Playlist remain unsupported. Its Project tab shows the current project's channels, patterns, and plug-in state; Plugins lists scanned candidates; Favorites persist starred file and plug-in paths; Recent keeps projects opened during the session. Search filters the current folder, plug-in list, or favorites. Clicking a supported audio file opens a Preview player at the bottom of the Browser and starts a five-second preview; **Full sample**, Play-to-end, volume, and Stop controls are available, and preview mixes with project output. Tempo/pitch synchronization, seeking, looping, tagging, recursive indexing, and other drag-and-drop loading remain incomplete; preview currently supports mono or stereo WAV, AIFF, FLAC, MP3, M4A (AAC/ALAC), Ogg, and WavPack files.

**Stamp** mode places a selected chord on a grid click. The chord menu includes common manual qualities and scale-derived triads/sevenths; note lengths use the active snap. **Only one** returns to Draw after a stamp. Automatic top-down/bottom-up voicing and voice leading are not implemented yet.

The Piano roll's **Selection** menu provides Select all, Invert selection, and Deselect commands, with Ctrl/Cmd+A, Shift+I, and Ctrl/Cmd+D shortcuts. These operate on the current pattern and channel.

Shift+G groups selected notes and Alt/Option+G ungroups them. Clicking, box-selecting, moving, resizing, or deleting a grouped note applies to its group.

The Piano roll's **Events** panel displays per-note velocity, pan, release, fine pitch, Mod X, or Mod Y as draggable stems. Select a target from the toolbar menu or press Shift+F to cycle through them. Pattern-scoped controller automation and event interpolation are not implemented yet.

The selected-note inspector can toggle a **Slide** note flag and shows a small marker at the start of the note. The flag is preserved in the FLP, but native-instrument glide playback and portamento remain unsupported.

Use Ctrl/Cmd+B or **Selection → Duplicate to right** to copy the selected notes, or all notes in the current channel when nothing is selected. The copy preserves note properties and moves right by the notes' combined time span; a separate time-range repeat interval is not available yet.

**Slice channel/selected** and `slice-notes` split targeted notes that cross the chosen tick into two notes. Both pieces retain the source note's properties.

The desktop executable also accepts an `.flp` path as its first argument to open that project at startup.

The **Project Info…** control edits the project's title, author, genre, comments, and web link. `project-info` prints those fields; `set-project-info` accepts `-` for fields to leave unchanged and an empty quoted string to clear a field. Missing fields are inserted before the first channel marker, and all other event bytes remain unchanged.

The **Project settings…** control edits the currently mapped Advanced options: “Play truncated notes in clips” and “Fast declick for cut groups.” It also reads and edits project pan law: Circular (`0`, the default) or Triangular (`2`), and the project-wide time signature. `project-settings` prints the mapped values; `set-project-settings` accepts `0`, `1`, or `-` for each Advanced field and an optional raw pan-law byte (or `-`). `set-project-time-signature` writes the project numerator and denominator. These are the project defaults; Playlist and Pattern time signatures are separate. In the Piano roll, **Pattern time signatures** can be added, updated, and deleted at tick positions with **Shift+Ctrl/Cmd+P**; meter changes are shown as bar divisions in that Pattern's grid. The `patterns` command lists signatures, while `set-pattern-time-signature` and `delete-pattern-time-signature` edit them by Pattern ID and tick. The Channel Rack also reads and edits its global swing amount through the `0x0B` project event; `global-swing` reports it and `set-global-swing` accepts 0–100 percent. Supported Pattern playback shifts every second 16th-step onset using the combined global and source-channel swing mix. The one-third-step maximum is an inferred triplet mapping and still needs comparison with native FL Studio audio. Master pitch, metronome, recording settings, and the remaining project controls are not yet decoded.

`create-pattern` adds an empty pattern after the highest recognized pattern ID. It only works when the project has a unique, recognized `D0` or `E0` note-event encoding; ambiguous or unrecognized layouts are refused without editing the source.

`edit-note-properties` updates a note's raw flags/group, fine-pitch, release, raw MIDI-channel, pan, and modulation X/Y fields. Pass `-` for any property to leave it unchanged. The reserved byte remains untouched.

`quantize-notes` moves note starts toward the nearest grid points for one pattern channel. Strength and swing are fractions from `0` to `1`; lengths and other note properties are retained.

In the Piano roll, **Quantize selected** targets the current selection. The **Edit** target selector routes other note-transform buttons to **Auto** (use the selection when present, otherwise the channel), **Channel**, or **Selected notes**.

The Piano roll's **Edit** target selector applies note-transform buttons to either the whole channel or only selected notes. **Legato channel/selected** extends targeted notes to the next distinct onset in the channel; notes in the final onset group keep their current lengths.

**Chop channel/selected** and `chop-notes` divide eligible notes into equal segments. Each new segment retains the source note's properties; any leftover ticks stay in the final segment.

**Glue channel/selected** and `glue-notes` join touching or overlapping targeted notes when all stored properties besides position and length match.

**Flip channel/selected** and `flip-notes` mirror note positions around the end of the latest channel note or, for a selection, within the selected notes' time bounds. Note lengths and other properties are retained.

**Strum channel/selected** and `strum-notes` stagger simultaneous targeted notes by pitch over the configured tick spread. Choose low-to-high (`up`) or high-to-low (`down`); note lengths and other properties are retained.

**Flam channel/selected** and `flam-notes` add a short same-pitch stroke for each targeted note. Set stroke time and velocity, and choose before or after placement. Before strokes earlier than tick zero are clamped to tick zero. Tempo-based timing, presets, and grouping are not implemented.

**Randomize channel/selected** and `randomize-notes` apply repeatable seeded changes to targeted note velocity, pan, and pitch. Velocity and pan amounts range from -100 to 100 percent; pitch range is 0 to 24 semitones. Bipolar mode allows changes in either direction, and Reset levels first uses velocity 100 and centered pan as the starting values. Scale-aware sequence generation remains incomplete.

**Humanize channel/selected** and `humanize-notes` apply seeded onset shifts within a symmetric tick range and velocity variation within a symmetric percentage range. Note lengths and other properties are retained. Tempo-relative timing remains incomplete.

**Limit channel/selected** and `limit-notes` fold targeted note pitches by octaves into the chosen key range, then clamp notes whose pitch classes cannot fit. The Piano roll can also wrap notes to the lowest octave in the range and snap out-of-scale pitches to the currently selected key and scale, upward, downward, or alternating. The CLI remains range-only; native alternate-snap edge behavior has not been compared.

**Arpeggiate channel/selected** and `arp-notes` replace targeted simultaneous chord groups with repeated up, down, or up/down note runs across a configurable octave range. Step time and gate length are configurable. Custom `.fsc` arp patterns, alternate patterns, and native sync modes are not implemented.

**Riff machine channel/selected** uses the targeted notes as a progression, builds diatonic triads in the current Piano roll scale, arpeggiates them, and applies seeded velocity variation, note-length scaling, and key-range fitting. It does not yet provide native progression presets, mirror and groove stages, custom patterns, or staged preview ([FL Studio Riff Machine manual](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/pianoroll_riff.htm)).

**Claw machine channel/selected** gates notes on a repeating period, slews their timing toward the period start or end, can remove notes shorter than one period slice, and can stretch notes across gaps left by removed notes. Its 16-slice gate and timing curve are local interpretations; native note-splitting and exact distortion behavior remain unverified ([FL Studio Claw Machine manual](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/pianoroll_claw.htm)).

**Slice channel/selected** splits targeted notes that cross the configured tick, retaining their note properties. The drag-based directional Slice tool remains incomplete.

The Piano roll key and scale selectors highlight C through B in major, natural minor, harmonic minor, and major or minor pentatonic scales. Selecting **None** disables highlighting; the helper does not constrain note entry.

When a note is selected, the inspector names a recognized chord made from notes at the same onset in the target channel. It detects common triads, suspended chords, seventh chords, and power chords; inversions and more complex voicings appear as a note count.

The Piano roll's **Ghost channels** toggle shows every channel in the current pattern in muted blue-gray while keeping the target channel green. Ghost notes remain editable through the same note controls.

Enable **Color by MIDI channel** to assign each note's stored low four MIDI-channel bits a distinct display color. Native color groups and color-based selection remain undecoded.

`edit-clip-properties` edits a clip's raw item/track/group/flags fields, source offsets, and scale when that field is present. Use `-` to leave a value unchanged; scale edits are rejected for layouts without the established scale field. `edit-playlist-track <input.flp> <output.flp> <track-id> <enabled:0|1|-> <grouped:0|1|->` updates the observed mute/group fields on an existing Playlist track while preserving its other event bytes.

`duplicate-clip` copies a clip's complete record and inserts it after the source. Its default position is the source clip's end; an optional position and raw track index can be supplied.

`channels <file.flp>` reports each channel's raw kind, known type label, observed Layer child IDs/flags, sample source path, volume, pan, and raw per-channel swing mix. Sample paths are decoded from `0xC4` for kind-0 Sampler channels and kind-4 sample-backed channels; plugin channel payloads remain excluded. Known type labels cover Sampler, Native, Layer, Instrument, and Automation; unrecognized raw values remain available. Layer Random and Crossfade can be toggled in the Channel Rack or with `set-layer-flags`, preserving all other `0x90` bits. `mixer <file.flp>` reports recognized Mixer insert names and raw fields from the observed `0x9A`/`0x93`/`0x95` sequence, plus the count of fixed-size `0xE1` parameter records. It does not yet map those parameter records to faders, effect slots, or routing controls. `sample-paths <file.flp>` tries to resolve each reference using the project folder, configured factory roots, and common FL Studio install locations; it reports paths it cannot find. Set `FL_STUDIO_ROOT` or `FL_STUDIO_FACTORY_DATA` to select a custom installation. `audio-info <audio-file>` decodes WAV, OGG/Vorbis, FLAC, MP3, AIFF, and lossless mono/stereo WavPack media by content, including FL Studio's private RIFF wrapper around Ogg data. `render-audio-clips <project.flp> <output.wav>` makes an experimental stereo float render of enabled Playlist clips that target audio channels, using the base project tempo and observed source offsets. Clips with non-default scale are skipped and counted. The Playlist transport mixes audio clips, supported Sampler notes, and mapped VST3 instruments placed by Pattern Clips in bounded worker blocks at the device rate. Opening a project auto-loads recognized VST3 channels when an installed bundle matches; unsupported or missing plug-ins are reported. VST3 output is resampled and mixed from the same instances used by open editors. It applies provisional channel volume/pan mapping and inferred pattern repeat behavior, which still need comparison against native FL Studio output. Pattern Sampler and VST3 notes use the same swing scheduler; Playlist audio clips are unaffected. Automation, routing, tempo changes, and Mixer effects are not yet part of Song transport.

`time-markers <file.flp>` lists arrangement time markers with positions, names, signature status, and meter values. It prints the raw position dword so unknown bits remain visible. `edit-time-marker` changes an existing marker's position, kind, meter, or name; `create-time-marker` inserts a time or signature marker in event order; and `delete-time-marker` removes the marker's recognized position, meter, and name events. These operations preserve unrelated events. The Playlist desktop view also displays marker lines and lets you select, edit, create, and delete markers. Its playhead follows device-consumed frames at the project's base tempo; seeking to markers and tempo-automation timing remain incomplete.

`pattern-controllers <file.flp> <pattern-id>` lists candidate raw controller records, including tick position, raw channel/flags/reserved fields, decoded float value, and original float bits. `edit-pattern-controller` updates one zero-based record; pass `-` to leave either field unchanged. `duplicate-pattern-controller` copies an existing point's opaque fields and sets a new tick position and value. `delete-pattern-controller` removes a point by zero-based index. In the Piano roll's **Events** lane, select **Raw controllers** to view points, filter by the exact stored channel/flags pair, drag to edit, click empty space to add a point from the selected stream, or right-click a point to delete it. Adding points requires at least one existing point in that stream so the opaque fields can be copied. Channel/flags meanings, native target mapping and scale, interpolation, and native save verification remain incomplete.

In the desktop Piano roll, **Open MIDI…** loads a MIDI file, lets you choose a track, and imports its notes into the selected pattern and channel. The selected track's note timing is converted from MIDI PPQ to project PPQ. **Export pattern MIDI…** exports the selected pattern; **Export song MIDI…** exports the selected Playlist arrangement. The Piano roll's MIDI channel mapping control preserves each note's stored low four channel bits or assigns one MIDI channel per FL channel. **Render WAV…** exports the selected pattern/channel through its loaded VST3 instance. **Preview VST3** processes that pattern in VST3-sized blocks on a worker and streams the stereo output through the selected device at its sample rate, using the same plug-in instance as the open editor. **Preview Samplers** streams enabled kind-0 Sampler notes from the selected pattern through the selected output. **Render Playlist mix…** renders supported audio clips, Sampler Pattern Clips, and mapped installed VST3 instruments in bounded blocks to WAV (16/24-bit integer PCM or 32-bit float), FLAC (16/24-bit integer), Ogg Vorbis (64–450 kbps target average bitrate), or MP3 (32–320 kbps constant bitrate at 32/44.1/48 kHz), with stereo/merged-mono/left-only/right-only channels and 0-, 1-, 2-, or 5-second tails. TPDF dither is available for 16-bit WAV only; FLAC uses the encoder defaults; **Render audio clips…** exports enabled audio-channel clips using the selected WAV, FLAC, Ogg Vorbis, or MP3 format with matching depth/bitrate and channel-mode settings; MP3 uses 32/44.1/48 kHz only, while WAV also uses the shared PCM depth and dither options. **File > Export > Render selected Audio Clip…** writes the selected enabled audio-channel Playlist clip’s supported sample source in the chosen output format and stops at the clip’s Playlist endpoint. Choose whether the output starts at the clip start or preserves its song position; looping or stretching a clip beyond its source duration remains incomplete; **File > Export > Render Sampler pattern…** writes enabled Sampler notes from the selected pattern to WAV using the shared bit-depth, dither, and channel-mode settings. Song transport also schedules Sampler and loaded VST3 instrument notes from Playlist Pattern Clips; Layer notes route to enabled supported child channels, and Layer Random chooses one child per placed note using a stable pseudo-random choice shared by both renderers. This selection is not verified against FL Studio’s native Random sequence. Matching installed VST3 channels load when the project opens, while unavailable or unrecognized channels remain unmapped. Sampler playback uses a provisional C5 root, channel-level gain/pan mapping, and pattern-length inference; Layer level/pan, key/velocity splits, Sequential mode, Crossfade, envelopes, loops, Mixer routing/effects, and guaranteed underrun-free processing are not implemented.

The native full-song render is still incomplete: the desktop **Render Playlist mix…** action combines supported enabled audio clips, Sampler notes, and mapped installed VST3 instruments into bounded-block WAV (16/24-bit integer PCM or 32-bit float), FLAC (16/24-bit integer), Ogg Vorbis (64–450 kbps target average bitrate), or MP3 (32–320 kbps constant bitrate at 32/44.1/48 kHz). All formats support stereo/merged-mono/left-only/right-only channel modes and fixed 0/1/2/5-second tails after the last scheduled clip. TPDF dither is available for 16-bit WAV only; FLAC uses the encoder defaults. Resampling offers Linear, 6-point Hermite, or 16/24/32/64/128/256/512-point windowed-sinc (32-point sinc by default, with the last choice retained between launches), and uses the project's base tempo with provisional channel gain/pan and repeat behavior. Non-default scaled clips are skipped and reported; Mixer routing/effects, automation, plugin delay compensation, FL Studio's shaped dither and exact resampling kernels, normalization, effect-based tail detection, and native output comparison are not implemented. `render-pattern-vst3` renders one decoded pattern channel through a selected installed VST3 instrument to a 32-bit float WAV, scheduling notes from the project's PPQ and tempo and appending an optional release tail (2 seconds by default). `render-pattern-samplers <project.flp> <pattern-id> <output.wav> [sample-rate] [voice-limit]` renders enabled kind-0 Sampler notes from one pattern to stereo float WAV, with bounded voices and streaming preview support. Its default MIDI-60 root-key assumption, local 32-point sinc filter, gain/pan mapping, and note envelopes still need native comparison. `render-audio-clips` separately mixes Playlist clips targeting enabled audio channels into a stereo float WAV. These are early paths, not full FL Studio render parity. The reader exposes channel summaries (including kind-0 Sampler and kind-4 sample-backed channel paths), patterns and notes, Playlist track names and arrangement clips, and opaque channel plug-in payloads; most other event meanings remain opaque. `playlist` accepts an optional starting clip and count. `plugin-states` reports channel plug-in payload sizes and event indices without decoding them. `edit-note` changes an existing note's start, length, key, and velocity while retaining its other note fields. `add-note` appends a 24-byte note record to a pattern; for an empty pattern it uses a note-event encoding observed elsewhere in the project and refuses to guess when encodings conflict. `delete-note` removes a channel-scoped note by zero-based index. These note operations rewrite only the affected score event and its length prefix. `edit-clip` changes an existing Playlist clip's position and length while retaining the other record bytes; `edit-clip-properties` edits recognized raw fields, offsets, and scale without rewriting unrelated record bytes. `set-tempo` and `rename-channel` edit existing fields and preserve every unrelated event's original wire bytes. The CLI can create empty patterns when the note-event encoding is unambiguous and duplicate existing Playlist clips. It does not yet create channels or targetless clips.

The Standard MIDI File reader recognizes the `MThd` header and `MTrk` event streams, including running-status channel messages, meta events, SysEx, system messages, PPQ timing, and SMPTE timing at -24, -25, drop-frame -29.97, or -30 frames per second. `midi-info` reports track names, timing, paired note events, and tempo-map spans. `import-midi` appends notes from one MIDI track to an existing FLP pattern and channel. PPQ tempo changes and SMPTE clock times are converted to note positions at the project's existing tempo, preserving elapsed note timing while leaving the FLP tempo and unrelated event bytes unchanged. When a PPQ file has no tempo events, the project tempo supplies the source timing baseline. Unclosed MIDI notes use the remaining track duration, or one beat if the track ends at the note start. `export-midi-pattern` writes one pattern, while `export-midi-song` expands Pattern Clips in one arrangement; both write format-1 MIDI with project PPQ, base tempo, time signature, and named tracks. Song export also writes arrangement markers and time-signature changes to the conductor track. The optional `stored` mapping keeps the low four bits of each note's stored channel; `channels` assigns channel numbers by FL channel order, wrapping after 16. Arrangement export currently skips audio clips, rejects non-default Pattern Clip scale, and requires a Playlist layout the reader can decode. Tempo-map import is baked into note timing rather than creating FL tempo automation; automatic channel/pattern creation is not implemented yet.

`scan <directory>` inventories `.flp` and `.fst` files recursively, grouping successfully parsed files by project version, header format, and PPQ while reporting any unparsed files. `plugin-scan` lists VST3 bundles and VST2 DLL candidates in the conventional Windows plug-in folders without loading their code. `plugin-state-preview` reports a channel's opaque wrapper and plug-in payload sizes and leading bytes. `vst3-state-probe` loads a VST3 and restores the selected channel's field-53 component/controller records through the host snapshot interface. In the local ZENOLOGY project, the restored component stream matches nested FLP record 3 byte-for-byte; plug-in audio and parameter equivalence still require comparison against FL Studio. State layouts outside the recognized marker-12 record format are rejected with an error.

The original application's MIDI export experiments and their measured results are recorded in [`docs/oracle-experiments.md`](docs/oracle-experiments.md). `midi-events` displays a selected MIDI track's decoded events, including tempo and marker metadata, for further format comparison.

## Channel Rack colors, levels, and swing

`channels <file.flp>` reports raw channel color, volume, and pan values when present, along with observed sample source paths. The desktop Channel Rack exposes a per-row color swatch and picker. `set-channel-color <input.flp> <output.flp> <channel-id> <RRGGBB>` edits the RGB components and retains the fourth color byte. Color sorting follows hue from red through violet, with achromatic and uncolored channels afterward. Click a channel name to select it, Ctrl/Cmd-click to toggle it in the selection, Shift-click to extend a contiguous selection, or double-click to select all channels. The row context menu can add/remove a channel from the selection, select only that channel, and mute/unmute all selected channels. Per-row Up/Down controls reorder complete channel event blocks without changing channel IDs, and the Sort by menu orders channels by color, name, or type. Right-click a channel name and choose Piano roll to open that channel in the selected pattern. The Channels menu offers Zip selected, Unzip selected, and Unzip all; Alt/Option+Z zips the selection and Alt/Option+U unzips all; per-row context menus zip or unzip one channel. `set-channel-levels` edits those first two fields and preserves the remaining event payload. `set-channel-swing <input.flp> <output.flp> <channel-id> <percent-0..100>` edits the channel swing multiplier; its `0x61` word stores 0–128, with 128 meaning 100% and a missing event defaulting to 100%. The Channel Rack header exposes global swing, while each row context menu edits its own multiplier. Both menus offer FL-style 0/25/50/75/100% presets and a custom percentage slider. Global swing is stored in project event `0x0B` (byte, 0–128, default 0) and per-channel swing in channel event `0x61` (word, 0–128, default 128). Pattern playback applies both values to aligned 16th-step onsets; the one-third-step maximum is inferred and needs native FL Studio render comparison. Older byte and word controls are decoded for inspection but remain read-only until their scaling is verified. Playlist audio and Sampler playback apply provisional volume/pan mappings based on observed raw defaults; native FL Studio output has not yet been used to verify the curves.

The Channel Rack step grid selects a pattern and bar, then toggles notes at sixteenth-note positions. New steps use key 60, one step of length, and velocity 100. Open the Graph Editor with Ctrl/Cmd+K to view and edit per-step note key, velocity, pan, release, fine pitch, modulation X/Y, and shift; drawing on an empty step creates a C5 note, right-dragging across steps interpolates a ramp, Ctrl-drag adjusts all active values together, and Alt/Option-click or drag resets active values to the lane default.

## Layer children

Layer child relationships and raw flags are available in the project model. The desktop Channel Rack exposes a child selector with channel names and IDs; `set-layer-children` replaces a Layer channel's repeated `0x5E` references while retaining other channel events. Pass comma-separated child IDs or `-` to clear the list. Playlist pattern notes route through enabled Sampler and mapped VST3 children. The Random option selects one child per note using a stable pseudo-random choice; the exact native sequence, Sequential mode, keyboard/velocity ranges, Layer level/pan adjustment, and Crossfade remain incomplete.

## Mixer

The `mixer <file.flp>` command reports recognized insert fields and counts known `0xE1` parameter IDs. The desktop Mixer presents recognized insert records as selectable vertical strips, with a Track Inspector for existing names and raw route, color, icon, and event-range fields. Names can be edited through their `0xCC` events while retaining the project's string encoding and unrelated bytes. A strip shows editable raw volume and pan controls only when the corpus-derived target convention finds one unique zero-scope record for each; the target-to-visible-track mapping remains unverified. The inspector shows ten disabled effect-slot placeholders while the slot data remains opaque. Its expandable `0xE1` record list edits raw signed values by exact event and record index, and shows target and slot bits as candidates. Meters, effect identity/state, and routing remain incomplete.

## Automation points

`automation <file.flp>` lists point curves from type-5 automation channels. `edit-automation-point` changes an existing point's position in beats, normalized value, and tension. `insert-automation-point` inserts at a zero-based slot (including the slot after the last point), and `delete-automation-point` removes a point by zero-based index. These operations preserve existing point tails and the blob's header and era trailer; new points use a zeroed opaque tail. They require a channel with an existing `0xEA` point blob. The desktop Automation view draws a type-5 curve and supports point selection, drag and numeric editing, insertion, and deletion. Its current preview uses straight segments and does not render tension/interpolation modes. Parameter links, event automation, automation-clip creation, and FL Studio's window-level curve workflow remain incomplete.

## Automated checks and installers

GitHub Actions runs formatting checks, Clippy, and the Rust test suite on Ubuntu, macOS, and Windows for pushes, pull requests, and manual runs. Each platform job also builds a native desktop package with Cargo Packager. CI uploads a Windows NSIS installer and Linux Debian, AppImage, and pacman packages; macOS uploads a signed and notarized DMG when Apple signing secrets are configured, or an unsigned GUI preview otherwise. Gatekeeper may block the preview until its quarantine attribute is removed; see [macOS CI packaging](docs/macos-ci-packaging.md). The package definitions are in [`Packager.toml`](Packager.toml).

## Compatibility plan

1. Project containers: broaden FLP envelope compatibility across releases, add semantic FST preset support, and complete ZIP package sample collection and validation.
2. Musical model: broaden pattern and note editing, then decode channel and plugin state, Playlist clip variants, automation, mixer routing, and audio-channel clip state, while retaining unsupported fields.
3. Interchange: MIDI import/export and audio export with stable timing and channel mapping.
4. Playback: connect the shared/exclusive live device engine to transport, tempo clock, sample scheduling, mixing, and automation.
5. Instruments and effects: continue VST3 hosting from the current project-open loading and state-restore subset, native editor window, parameter-list prototype, and single-pattern offline render into broader project-state support, state write-back, automation, MIDI/audio routing, Mixer processing, and whole-project rendering. Add VST2 hosting if an applicable legacy licensing path is available. Preserve plug-in identity and opaque state when a plug-in is unavailable. Rebuilding FL's bundled plug-in DSP is out of scope.
6. User experience: project browser, Playlist, piano roll, channel rack, mixer, plugin windows, editing tools, shortcuts, and accessibility.
7. Historical compatibility: fixture-driven support across older FLP versions, with explicit reporting where a project depends on unavailable plugins or media.

Full feature parity is a long-running objective. Each milestone should keep unsupported project data intact so opening and saving a project does not silently destroy state. Installed plug-ins are treated as external instruments/effects to host, rather than DSP to reimplement.
