# Rust DAW compatibility rebuild

## Parity progress — 2026-10-23

**Early prototype; not yet suitable as a full FL Studio replacement.** The [parity roadmap](docs/parity-roadmap.md) is an unweighted checklist: partial items cover only their stated subsets, and a completed small item does not count as the same amount of work as a complete subsystem.

- **Working foundations:** lossless FLP parsing and round-trip writing, selected project and note edits, MIDI import and partial export, and cross-platform CI packaging.
- **Partial runtime and editing:** early Playlist, Channel Rack, Piano roll, Mixer, plug-in, and audio views; the Piano roll includes a saved Grouping switch and repeatable Magic Lasso selection; Windows shared and exclusive audio; playback and a first combined WAV render for supported audio clips, Sampler notes, and mapped installed VST3 instruments. Loaded VST3 instances support a machine-local manual PDC offset per class UID, added to reported latency. Supported Mixer direct and complete send paths include live fader, pan, stereo-width, phase, and channel-swap smoothing. Direct-to-Master sources smooth live mute changes, and direct plus complete send-routed paths smooth live solo changes; route and parameter mappings remain provisional.
- **Major parity gaps:** native-verified Mixer mappings, manual per-track PDC offsets, sidechain audio, broad automation parity, VST compatibility and state write-back, full FL Studio window/control behavior, and verified compatibility across FL Studio versions.

See the roadmap for subsystem-level status and evidence.

This is a clean-room Rust project started from the FL Studio 26.1.6.5639 installation supplied with the workspace. It is an independent rebuild; it does not load, patch, or link against the installed FL Studio executable or engine. The end goal is to open and modify any FL Studio project with backwards compatibility, matching controls, windows, and editing behavior, installed plug-in hosting, playback, and rendering. The current code contains the lossless file-format core and the first desktop editing shell; it is still far from full parity.

The first milestone is deliberately a compatibility foundation: inspect FL Studio project (`.flp`) files and preserve every event, including data the reader does not understand. The reader identifies common `.fst` header variants for channel, native plug-in, VST generator/effect, and Mixer insert states; plugin payloads are still opaque. FL Studio's own documentation describes `.flp` as its native project format, `.fst` as a state/preset format, and ZIP project packages as projects bundled with referenced sample files. The installed projects and presets provide a local compatibility corpus.

The desktop app also opens standard `.zip` project packages, extracts their regular files to a temporary workspace for relative sample lookup, and writes edited FLP data back while retaining the other files. Saving a plain `.flp` as `.zip` bundles resolvable Sampler and Audio Clip samples under `Samples/`; missing sample references remain external and are reported.

## Current milestone

`flp-rebuild` can read the FLP chunk envelope and event stream, report header information, event counts, channel summaries, and a small set of project fields, and write a lossless round-trip copy. `preset-info` classifies known FST state-file variants and reports their decoded structure. Format-1 imports read meter changes across tracks, while format-0 and format-2 imports read the selected track. Marker positions follow the MIDI tempo map or SMPTE clock and are converted to the existing project's tempo/PPQ grid. The importer snapshots MIDI CC 10 pan, CC 74 Mod X, CC 71 Mod Y, and pitch bend at each Note On into the corresponding FL note properties. MIDI CC 64 sustain extends each released note through pedal-up; CC 66 sostenuto holds only notes already active when the pedal transitions down. If both pedals hold a note, it ends when the last holding pedal goes up, retaining the paired Note Off release velocity. CC 120 All Sound Off ends active and pedal-held notes immediately on its channel. CC 123–127 end active notes like Note Off and respect both pedals; because these controllers carry no release velocity, imported notes use the default FL note release. CC 121 Reset All Controllers ends deferred notes and restores imported controller snapshots to their defaults. Missing CC 10/74/71 values use center 64, which maps to FL Mod X/Y default 128; pitch sensitivity follows MIDI RPN 0 when present or assumes ±2 semitones otherwise. Later pan, Mod X/Y, or bend changes during held notes remain unimported. PPQ tempo changes and SMPTE clock times are converted to note positions at the project's existing tempo, preserving elapsed note timing while leaving the FLP tempo and unrelated event bytes unchanged. When a PPQ file has no tempo events, the project tempo supplies the source timing baseline. Unclosed MIDI notes use the remaining track duration, or one beat if the track ends at the note start. `export-midi-pattern` writes one pattern, while `export-midi-song` expands Pattern Clips in one arrangement; both write format-1 MIDI with project PPQ, base tempo, time signature, and named tracks. Both exports write note pan as MIDI CC 10, mapping FL's 0–128 range to 0–127 with 64 at center. Note Mod X/Mod Y map to MIDI CC 74 (brightness/filter cutoff) and CC 71 (timbre/harmonic intensity), scaling FL's 0–255 range to 0–127. Overlapping notes with different pan, Mod X/Mod Y, or pitch use spare MIDI channels when available; otherwise export returns an error. These controller mappings are export extensions pending comparison with FL Studio's native MIDI export. Song export also writes arrangement markers and time-signature changes to the conductor track. The optional `stored` mapping keeps the low four bits of each note's stored channel; `channels` assigns channel numbers by FL channel order, wrapping after 16. Arrangement export currently skips audio clips, rejects non-default Pattern Clip scale, and requires a Playlist layout the reader can decode. `export-midi-cc` exports one raw Pattern controller stream as a format-1 MIDI file with conductor tempo/meter data; the raw channel/flags, MIDI CC number, and one-based MIDI channel are supplied explicitly because the stream does not encode those mappings. Pattern ticks and project PPQ are preserved, and values clamp to 0.0–1.0 before mapping to MIDI 0–127. Tempo-map import is baked into note timing rather than creating FL tempo automation. `import-midi-cc` imports one selected MIDI Control Change number from a track into a chosen existing raw Pattern controller stream; `import-midi-cc-new-stream` creates a new raw stream from supplied channel/flags bytes. Both can filter to one MIDI channel, convert source tempo-map or SMPTE timing to project ticks, and map values from MIDI 0–127 to 0.0–1.0. A new stream starts at the first imported point and is not created when there are no matching CC messages. `import-midi-sampler-tracks <input.flp> <input.mid> <output.flp> <pattern-id> <template-channel-id>` creates one named kind-0 Sampler channel per format-0/1 track by copying an existing Sampler template. `import-midi-template-tracks` supports selected format-0/1 tracks, an existing or new Pattern, Sampler, MIDI Out, Native, or Layer templates, and MIDI import options; `import-midi-template-format2` creates a new Pattern and named channel copied from a Sampler, MIDI Out, Native, or Layer template for each selected independent Format-2 sequence. MIDI Out copies retain saved routing; Layer copies retain their saved child references. `import-midi-format2` retains its Sampler behavior for compatibility. `import-midi-new-project <template.flp> <input.mid> <output.flp> <template-channel-id> <track-numbers>` builds a separate project from an FLP template; format-0/1 tracks share one Pattern, while selected Format-2 sequences each receive a separate Pattern. The desktop can use the installed Empty.flp or a user-selected template. Other channel kinds remain unsupported for template-based MIDI import.

`export-midi-cc` writes one raw Pattern `0xDF` controller stream as a selected MIDI CC number and channel. `export-midi-song-cc` applies that mapping to every matching Pattern Clip in the selected arrangement, repeating events by the saved or note-inferred Pattern loop length when available, otherwise using one pass per clip, clipping at clip boundaries, and preserving the song export conductor data. The raw stream does not identify its MIDI controller or channel, so both are supplied explicitly; scaled Pattern Clips remain unsupported.
`scan <directory>` inventories `.flp` and `.fst` files recursively, grouping successfully parsed files by project version, header format, and PPQ while reporting any unparsed files. `plugin-scan` lists VST3 bundles and VST2 DLL candidates in the conventional Windows plug-in folders without loading their code. `plugin-state-preview` reports a channel's opaque wrapper and plug-in payload sizes and leading bytes. `vst3-state-probe` loads a VST3 and restores the selected channel's field-53 component/controller records through the host snapshot interface. In the local ZENOLOGY project, the restored component stream matches nested FLP record 3 byte-for-byte; plug-in audio and parameter equivalence still require comparison against FL Studio. State layouts outside the recognized marker-12 record format are rejected with an error.

The original application's MIDI export experiments and their measured results are recorded in [`docs/oracle-experiments.md`](docs/oracle-experiments.md). `midi-events` displays a selected MIDI track's decoded events, including tempo and marker metadata, for further format comparison.

## Channel Rack colors, levels, and swing

The Channel Rack inspector exposes the five ordered Sampler `0xDA` Envelope/LFO records as raw Panning, Volume, Mod X, Mod Y, and Pitch controls. The `channels` command prints the decoded records, and the generic editor can change envelope and LFO flags and raw fields while preserving unedited values, unknown flag bits, trailing bytes, and unrelated events. `edit-sampler-envelope-lfo` takes a target plus `-` for each field to leave unchanged; envelope and LFO time values use `100..=65536`, LFO speed uses `200..=65536`, sustain uses `0..=128`, amounts and tensions use `-128..=128`, and LFO shape uses 0 (Sine), 1 (Triangle), or 2 (Pulse). The older `edit-sampler-volume-envelope` command remains as a Volume-only compatibility command. These field meanings and ranges follow the third-party PyFLP parser and still need a controlled FL Studio save comparison. Playback still uses only the saved Volume-envelope enabled flag with its generic release behavior; envelope curves, tempo sync, and all LFO modulation are not applied to audio.

`channels <file.flp>` reports raw channel color, volume, and pan values when present, along with observed sample source paths, enabled state, zipped state, Enable main pitch, Add to Key, and the decoded playable key region. `set-channel-enabled <input.flp> <output.flp> <channel-id> <0|1>` edits the saved enabled/muted state, preserving other channel events and inserting the state event when needed. `set-channel-sample-path <input.flp> <output.flp> <channel-id> <sample-path>` changes the recognized `0xC4` path on an existing Sampler or Audio Clip channel while preserving its project string encoding and unrelated events. `set-channel-zipped <input.flp> <output.flp> <channel-id> <0|1>` edits the compact Channel Rack state, inserting the event after the channel kind when needed. Zipped rows keep their step cells inline and hide secondary controls. The desktop Channel Rack exposes a per-row color swatch and picker plus compact type icons with hover descriptions. Sampler, generator, Layer, Instrument, and Automation kinds use distinct glyphs; unknown kinds show their raw type value. `set-channel-color <input.flp> <output.flp> <channel-id> <RRGGBB>` edits the RGB components and retains the fourth color byte. `set-channel-colors` applies one color to the listed channel IDs. `set-channel-color-gradient` applies a linear RGB gradient in the supplied channel order, from the start color on the first channel to the end color on the last; it requires at least two unique IDs. Both operations preserve existing fourth color bytes. `move-channel` moves one row to a zero-based target index. `reorder-channels` takes a complete permutation of every channel ID. `sort-channels` accepts color, mixer-track, name, or type. Color sorting follows hue from red through violet, with achromatic and uncolored channels afterward. Click a channel name to select it, Ctrl/Cmd-click to toggle it in the selection, Shift-click to extend a contiguous selection, or double-click to select all channels. The row context menu can add/remove a channel from the selection, select only that channel, and toggle Enable main pitch and Add to Key on supported channel types. The Channel Rack’s **Playable key range** controls edit an existing inclusive key region; `set-channel-key-region <input.flp> <output.flp> <channel-id> <low-key> <high-key>` updates a unique recognized Parameters event and preserves its other bytes. The Channel Rack also applies one color transactionally to every selected channel, interpolates a linear RGB gradient from the first to last selected row's stored colors, and mutes or unmutes all selected channels. `set-channel-main-pitch <input.flp> <output.flp> <channel-id> <0|1>` edits Enable main pitch; `set-channel-add-to-key <input.flp> <output.flp> <channel-id> <0|1>` edits Add to Key. Supported Sampler and hosted VST3 notes use continuous cents pitch unless Add to Key is enabled, which transposes them by the nearest semitone; unstretched Playlist Audio Clips (scale unset or 1.0) use continuous project Master pitch. VST3 Root Key offsets, native instruments, and stretched Audio Clips remain incomplete. Per-row Up/Down controls reorder complete channel event blocks without changing channel IDs, and the Sort by menu orders channels by color, name, or type. Right-click a channel name and choose Piano roll to open that channel in the selected pattern. The Channels menu offers Zip selected, Unzip selected, and Unzip all; Alt/Option+Z zips the selection and Alt/Option+U unzips all; per-row context menus zip or unzip one channel. `set-channel-levels` edits those first two fields and preserves the remaining event payload. `set-channel-swing <input.flp> <output.flp> <channel-id> <percent-0..100>` edits the channel swing multiplier; its `0x61` word stores 0–128, with 128 meaning 100% and a missing event defaulting to 100%. The Channel Rack header exposes global swing, while each row context menu edits its own multiplier. Both menus offer FL-style 0/25/50/75/100% presets and a custom percentage slider. Global swing is stored in project event `0x0B` (byte, 0–128, default 0) and per-channel swing in channel event `0x61` (word, 0–128, default 128). Pattern playback applies both values to aligned 16th-step onsets; the one-third-step maximum is inferred and needs native FL Studio render comparison. Older byte and word controls are decoded for inspection but remain read-only until their scaling is verified. Playlist audio and Sampler playback apply provisional volume/pan mappings based on observed raw defaults; native FL Studio output has not yet been used to verify the curves.

The `channel-groups` command lists zero-based group indices, names, and member channel IDs. `create-channel-group` adds an empty group; `group-channels` creates or reuses a group with an exact matching name and assigns the listed channel IDs; `rename-channel-group` changes a group's name; `delete-channel-group` unassigns its channels and shifts higher group indices down.

The Channel Rack step grid selects a pattern and bar, then toggles notes at sixteenth-note positions. New steps use key 60, one step of length, and velocity 100. Cells show counts when multiple notes fall in one step; clicking a populated cell removes all of its notes, and right-clicking opens a key selector to add another note at that step. Open the Graph Editor with Ctrl/Cmd+K to view and edit per-step note key, velocity, pan, release, fine pitch, modulation X/Y, and shift; drawing on an empty step creates a C5 note, right-dragging across steps interpolates a ramp, Ctrl-drag adjusts all active values together, and Alt/Option-click or drag resets active values to the lane default.

## Layer children

Layer child relationships and raw flags are available in the project model. The desktop Channel Rack exposes a child selector with channel names and IDs; `set-layer-children` replaces a Layer channel's repeated `0x5E` references while retaining other channel events. Pass comma-separated child IDs or `-` to clear the list. Playlist pattern notes route through enabled Sampler and mapped VST3 children. The Random option selects one child per note using a stable pseudo-random choice; the exact native sequence, Sequential mode, keyboard/velocity ranges, Layer level/pan adjustment, and Crossfade remain incomplete.

## Mixer

The `mixer <file.flp>` command reports recognized insert fields and each `0xE1` parameter record's global event index, record index, raw ID, candidate target/slot bits, and signed value. Its output also lists saved send levels and any paired routing flag event/byte location. For a Mixer effect slot with exactly one recognized marker-12 VST3 `0xD5` state event, it also reports the class UID and nested state size; the host API restores that state only into a loaded audio effect with a matching UID and can encode edited component/controller state back into the nested FLP stream. The document API writes that stream into field 53 while retaining other wrapper fields and events. `set-mixer-parameter-record-value <input.flp> <output.flp> <event-index> <record-index> <signed-value>` changes one record's signed value while retaining its prefix, ID, target word, and other records. The desktop Mixer presents recognized insert records as selectable vertical strips, with a Track Inspector for existing names and raw route, color, icon, and event-range fields. `rename-mixer-insert <input.flp> <output.flp> <insert-ordinal> <name>` edits an existing `0xCC` name event while retaining the project's string encoding, terminator convention, and opaque tail bytes. `set-mixer-insert-flag <input.flp> <output.flp> <insert-ordinal> <field> <0|1>` edits one existing flag (`enabled`, `soloed`, `polarity-reversed`, `swap-left-right`, or `effects-enabled`) while preserving reserved and unknown bits. `set-mixer-routing-flag <input.flp> <output.flp> <event-index> <flag-byte-index> <0|1>` toggles one existing send-routing flag byte at the location reported by `mixer`. A strip shows editable raw volume and pan controls only when the corpus-derived target convention finds one unique zero-scope record for each; a unique in-range stereo-separation record also gets an editable raw slider. The target-to-visible-track mapping remains unverified. The inspector shows each recognized effect slot and exposes its saved enabled state plus a raw Mix slider when unique, unscoped 0xE1 records use the candidate 64 + insert ordinal mapping. The raw Mix edit range is -6400 through 6400; duplicate, scoped, missing, and out-of-range records stay read-only. The `Move up` and `Move down` controls, pointer drag-and-drop, `move-mixer-effect-slot <input.flp> <output.flp> <insert-ordinal> <from-slot-0..9> <to-slot-0..9>`, and the library API move a slot together with its opaque state events and remap recognized enable/Mix records. Reordering is rejected if unknown slot-parameter records could be affected. Its expandable `0xE1` record list edits raw signed values by exact event and record index, and shows target and slot bits as candidates. Recognized marker-12 VST3 effects auto-load when a matching bundle is installed, restore the saved state, expose an Open editor action in the Mixer slot, and write edited state back when the project is saved; loaded VST3 Mixer effects process on known inserts with route-level PDC across supported saved sends; unsupported route mappings, manual offsets, sidechains, and offline insert metering remain incomplete. Live Master and recognized direct-route insert peak meters are available. Supported non-Master Audio Clip, Sampler, and loaded VST3 sources follow live Mute, phase-invert, and left/right-swap changes on direct and complete send routes with a 20 ms source smoother during playback.

The Mixer inspector also shows unique, unscoped three-band EQ gain, frequency, and Q values as raw controls. `set-mixer-eq-parameter-raw` accepts `low-gain`, `mid-gain`, `high-gain`, `low-frequency`, `mid-frequency`, `high-frequency`, `low-q`, `mid-q`, or `high-q`; gain is bounded to -1800 through 1800 and frequency/Q to 0 through 65536. The candidate `64 + insert ordinal` mapping is used. Frequency values are nonlinear, duplicate or scoped records remain unavailable, and editing saved EQ values does not process audio.

## Automation points

`automation <file.flp>` lists point curves from type-5 automation channels. `edit-automation-point` changes an existing point's position in beats, normalized value, and tension. `insert-automation-point` inserts at a zero-based slot (including the slot after the last point), and `delete-automation-point` removes a point by zero-based index. `interpolate-automation-points` linearly fills the values of points strictly between two existing endpoint indices, leaving the endpoints, positions, tensions, and opaque data unchanged; it reports how many points it changed. These operations preserve existing point tails and the blob's header and era trailer; new points use a zeroed opaque tail. `init-automation-points` creates a zero-point blob on a type-5 channel by copying the 17-byte header and era trailer from another type-5 channel in the same project, without copying its points. This provides a template-based starting point when the target channel has no `0xEA` event; native header/trailer generation without a template remains unsupported. The desktop Automation view offers the same initialization from another saved Automation channel, and draws a type-5 curve with point selection, drag and numeric editing, insertion, deletion, and linear interpolation of point values between two endpoints. The preview uses straight segments and does not render FL tension/interpolation modes. Parameter links, event automation, automation-clip creation, and FL Studio's window-level curve workflow remain incomplete.

The Automation panel also reads and edits each saved automation channel's bipolar LFO amount through the project API and CLI. The `set-automation-lfo-amount` command accepts raw values from -128 through 128 and preserves the curve points and opaque event bytes.

## Automated checks and installers

GitHub Actions runs formatting checks, Clippy, and the Rust test suite on native x64 and ARM64 runners for Linux and Windows, and on Apple Silicon for macOS. Each job builds and launches its desktop app. CI uploads a macOS ARM64 DMG; Windows x64 and ARM64 setup installers; and, for both Linux architectures, AppImage, Debian (`.deb`), RPM (`.rpm`), and Arch (`.pkg.tar.zst`) packages. Linux package metadata and executable architectures are checked before upload. Artifacts are named `installers-<platform>` and retained for 14 days. The macOS DMG is signed and notarized when Apple signing secrets are configured, and unsigned otherwise. See [macOS CI packaging](docs/macos-ci-packaging.md). The package definitions are in [`Packager.toml`](Packager.toml).

## Compatibility plan

1. Project containers: broaden FLP envelope compatibility across releases, add semantic FST preset support, and complete ZIP package sample collection and validation.
2. Musical model: broaden pattern and note editing, then decode channel and plugin state, Playlist clip variants, automation, mixer routing, and audio-channel clip state, while retaining unsupported fields.
3. Interchange: MIDI import/export and audio export with stable timing and channel mapping.
4. Playback: connect the shared/exclusive live device engine to transport, tempo clock, sample scheduling, mixing, and automation.
5. Instruments and effects: continue VST3 hosting from the current project-open loading and state-restore subset, native editor window, parameter-list prototype, and single-pattern offline render into broader project-state support, state write-back, automation, MIDI/audio routing, Mixer processing, and whole-project rendering. Add VST2 hosting if an applicable legacy licensing path is available. Preserve plug-in identity and opaque state when a plug-in is unavailable. Rebuilding FL's bundled plug-in DSP is out of scope.
6. User experience: project browser, Playlist, piano roll, channel rack, mixer, plugin windows, editing tools, shortcuts, and accessibility.
7. Historical compatibility: fixture-driven support across older FLP versions, with explicit reporting where a project depends on unavailable plugins or media.

Full feature parity is a long-running objective. Each milestone should keep unsupported project data intact so opening and saving a project does not silently destroy state. Installed plug-ins are treated as external instruments/effects to host, rather than DSP to reimplement.
