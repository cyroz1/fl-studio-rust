# FL Studio Full Parity & Compatibility Roadmap

What "done" means: open any `.flp` from any FL Studio version, play it back
sounding identical, edit it with the same tools, and save it back without data
loss. This document enumerates everything that requires, grouped by subsystem,
with the current status of this project against each item.

Status legend:

- `[done]` — implemented and working
- `[partial]` — started; works for a subset of cases
- `[todo]` — not started
- `[obsolete]` — removed from current FL Studio; not a current parity target
- `[not supported by FL Studio]` — no equivalent behavior exists in the native application

> Scope note: this covers the desktop DAW. FL Cloud, FL Studio Mobile, and
> online services are explicitly out of scope (see Non-goals).

---

The foundation. Everything else depends on reading projects exactly.

Pattern notes on Layers recursively route to enabled Sampler and mapped VST3 descendants; each nested Layer applies its own key region and Random choice, using stable per-note pseudo-random selection. Saved inclusive key regions from channel Parameters events (`0xC7`) filter source notes and children before selection. The model and `channels` command expose raw pan, volume, unknown, Mod X, and Mod Y fields from recognized channel `0xD5` Level Adjusts payloads. The API and `edit-channel-level-adjustments` CLI command can edit established fields in one event selected by its global event index while preserving the unknown field, trailing bytes, length prefix, and unrelated events; plug-in-tagged channels and recognized VST envelopes are rejected to avoid treating plug-in state as level data. Units and playback effects remain unverified. Layer Crossfade reads the saved `0xC7` Fade value (offset 88, range 0–256) and applies linear gains between adjacent active child subtrees when every leaf is an enabled, key-matching Sampler; nested Sampler-only Layers compose their gains during Pattern preview, Playlist playback, and supported renders. Native Random sequencing, Sequential mode, velocity ranges, applying Layer level/pan adjustments, and legacy channel types remain incomplete ([Image-Line key-region behavior](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/chansettings_misc.htm), [PyFLP Parameters layout](https://github.com/demberto/PyFLP/blob/master/pyflp/channel.py), [PyFLP Level Adjusts layout](https://pyflp.readthedocs.io/en/latest/_modules/pyflp/channel.html)). |

## 4. Native (stock) plugins

**Project decision (2026-10-06): stock plugin DSP is out of scope.** This
project will not reimplement Image-Line's instruments and effects. The
compatibility strategy for every stock plugin is a single one:

- **Host the original.** If the user has FL Studio (or the individual plugin)
  installed, load it like any other VST and restore its state from the FLP
  blob. A project opens and sounds right when the plugins are present;
  missing plugins are reported, not faked.

This removes the entire reimplementation surface (~110 plugins of proprietary
DSP: Sytrus, Harmor, FLEX, Gross Beat, Newtone, etc.). It also sidesteps the
legal risk of cloning trade-secret algorithms — hosting a plugin the user
legitimately owns is the standard DAW interop story.

What this still requires (tracked under §5, plugin hosting):

- Reliable VST2/VST3 state save/restore for Image-Line's own plugins, which
  use the same wrapper records as third-party plugins
- Graceful handling when a stock plugin isn't installed: show the channel,
  its settings blob size, and which plugin is missing — never silently drop
  the channel or corrupt the project
- `.fst` preset loading for Image-Line's native plugins and other VST wrapper
  layouts; format-32 channel-state presets now load into already hosted
  marker-12 VST3 channels when the class UID matches

No per-plugin DSP work is planned. If a stock plugin's state format ever needs
interpretation without the plugin present, that becomes a case-by-case
decision, not a roadmap item.

## 14. MIDI hardware & scripting

- `[partial]` MIDI input: the Audio settings view can list, refresh, connect, and disconnect hardware inputs. The selected input port ID persists in user settings, and an optional startup setting reconnects it when available; without that setting, the hardware connection remains manual. The transport Record button's context menu independently enables Audio, Notes, and CC automation, persists these choices, and starts or stops the enabled capture paths together. CC automation records one configured controller number into the selected Pattern's raw `0xDF` stream, using the configured stream channel and flags; values are normalized to 0–1 and repeated points at the same tick coalesce to the latest value. CC automation can be recorded with or without Notes. With Notes enabled, Record captures note-on/off events (including note-on velocity, release velocity, and MIDI channel) into the selected Pattern/channel; CC64 sustain defers captured note-offs independently per MIDI channel until pedal-up, CC121, or recording stop while retaining note-off release velocity. CC120 closes active and sustained notes on its input channel immediately; CC123–127 act as note-offs and respect sustain. CC 10 pan, CC 74 Mod X, CC 71 Mod Y, and pitch bend are snapshotted at each Note On. Pan maps to FL's 0–128 note-pan range; Mod X/Y map MIDI 0–127 to FL 0–255 with center 64 at FL default 128; bend maps to FL's 10-cent fine-pitch steps using received RPN 0 sensitivity or the default ±2-semitone range. Later pan, Mod X/Y, and bend changes do not alter notes already captured. Incoming MIDI release velocity maps from 0–127 to FL's 0–128 note-release range, while notes still held at stop keep the default release value 64. The whole capture is one undoable project edit. Input quantization can be disabled or set to quarter-beat, half-beat, beat, two-beat, or bar grids, or to 1/16, 1/8, 1/4, or 1/2 triplet grids; enabled quantization rounds note starts and ends to the nearest grid. A persisted option can ignore incoming note-on velocity and record every note at fixed velocity 100; device velocity remains the default. A persisted -200 to +200 ms timing offset can move captured events earlier or later to compensate for system latency. When recording begins during Playlist playback inside a Pattern Clip for the selected Pattern, captured note positions are offset from that clip's start; otherwise notes start at Pattern tick zero. During continuous Playlist playback, note timing follows the active arrangement's linear `TEMPO` map; timestamps use host time, so device latency, pauses, or output underruns can still shift capture timing. During Playlist playback, stopping a take that began outside a clip of the selected Pattern adds a Pattern Clip at the captured start position on the first free track; the new clip spans at least one bar and expands to contain the Pattern's notes. A take that starts inside an existing Pattern Clip extends that clip to include the captured notes when its source window is safely resizable. Notes remain saved if no clip template or free track is available. Song-position timing across repeated clips and resizing clips with unrecognized source windows remain incomplete. MIDI Start/Continue/Stop and MMC Play/Stop/Record commands operate the Playlist transport/recorder. Clock, song position, controller, pressure, and program messages are parsed for activity display and can be forwarded by MIDI Thru. When transport is stopped, incoming note-on/off events audition the selected Pattern’s enabled Sampler channel through a low-latency stream; the project must be saved so its sample paths resolve. A directly selected loaded VST3 channel can also be auditioned through a low-latency VST3 stream, which applies the channel’s saved key region and preserves note-off pairing for suppressed notes. A selected Layer can route live notes through its key regions and Random selection when its enabled descendants resolve to loaded VST3 channels, Samplers with resolvable saved-project sample paths, or a mix of both; nested Layers recurse through their child key regions and Random selection. Mixed Sampler audio is aligned to VST3 latency, and both destinations share the Layer’s note routing and controller input. The MIDI input scale-snap preference applies to all these destinations, and note-offs retain the mapped key if the setting changes while held. Sampler live audition applies CC 10 pan and CC 11 expression to new and already sounding voices per input channel; CC 120 immediately silences that channel’s voices, and CC 123–127 release its live notes while respecting sustain. CC 121 resets pan to center. Live loaded VST3 audition forwards incoming Control Change, Program Change, pitch bend, and channel/polyphonic aftertouch messages to the selected channel or its routed VST3 children, and synchronizes tracked pan, modulation, sustain, and bend state when audition starts. During Playlist playback, direct Sampler input overlays live audio and loaded VST3 input reaches an active Playlist processor; Pattern playback overlays Sampler input and routes VST3 input through the active Pattern stream. During Playlist, Pattern, and Performance playback, a selected Layer routes each note through its saved and nested key regions and Random selection to the matching live Sampler overlay and active VST3 processors; mixed Layer notes share the same Random choice and mapped note-off. Performance Mode reserves its configured MIDI channel (default channel 1) for clip and scene controls; other channels audition the selected Sampler, loaded VST3, or supported Layer through the active Performance stream. Broader controller mapping, native Automation Clip recording, and MIDI scripting remain incomplete ([Image-Line MIDI settings](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/envsettings_midi.htm), [Note/MIDI recording](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/recording_scores.htm), [Piano roll scripting API](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/pianoroll_scripting_api.htm), [MIDI 1.0 Control Change Messages](https://midi.org/midi-1-0-control-change-messages)).
- `[partial]` MIDI input scale snapping: an optional recording setting moves captured note pitches to the nearest note in the selected Piano roll scale, captured when the take begins. MIDI Thru also offers optional snapping of forwarded note-on/off pairs to the current Piano roll scale and root. This supports scale-constrained recording plus live Sampler, selected loaded VST3, and Layer input with Sampler-only, VST3-only, or mixed Sampler/VST3 descendants, including nested Layers. Direct Sampler input can be auditioned over Playlist audio, and loaded VST3 channels can receive live MIDI while their Playlist processors are active; Pattern mode overlays Sampler audio and routes VST3 input through active Pattern instruments. During Playlist, Pattern, and Performance playback, Layer notes use the same saved key regions, nested key regions, and Random choice for Sampler and active VST3 destinations, with note-offs sent to the destinations selected at note-on. Performance Mode reserves its configured MIDI channel (default channel 1) and auditions the selected Sampler, loaded VST3, or supported Layer on other channels. Recording captures the chosen scale at take start, live note-offs retain their snapped key across setting changes, and MIDI Thru keeps its independent snap option. Active Sampler voices follow incoming pitch bend continuously, including RPN 0 range changes. CC 10 updates live Sampler pan for held and new voices; CC 64 holds released voices until pedal-up, and CC 121 releases sustained voices and resets pan. Other internal destination snapping remains incomplete ([Image-Line Piano roll manual](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/pianoroll.htm)).
- `[partial]` MIDI Thru: Audio settings can forward incoming notes, controllers, pitch bend, clock, song position, and Start/Continue/Stop messages to the selected external MIDI output while both devices are connected. Enabling Thru is opt-in and session-only; scale snapping and output-channel override preferences persist across launches, with snapping off and input-channel preservation as defaults. A dedicated worker receives events directly from the MIDI input callback, so external Thru no longer waits for UI polling. Held notes keep their original output channel/key if settings change, and note-offs plus sustain-off are sent when Thru is disabled or either device disconnects. Forwarded CC 120 and CC 123–127 clear tracked notes on the affected output channel, and CC 121 clears tracked sustain state. If the bounded Thru queue fills, the worker releases tracked notes and ignores stale queued events. This supports external hardware audition; the internal live audition path also supports a selected loaded VST3 channel as described under MIDI input, while VST3 MIDI Thru routing and multi-channel internal routing remain incomplete. Device/driver send timing and queue overflow under sustained load remain limitations.
- `[partial]` MIDI output: Audio settings can enumerate, refresh, connect, and disconnect one external MIDI output interface. The selected output port ID and MIDI output options persist in user settings, and an optional startup setting reconnects it when available; without that setting, the hardware connection remains manual. Connect and disconnect send All Notes Off on all 16 channels; **Test C4** sends a short channel-1 note, and **Preview pattern** schedules valid notes from the selected Pattern using its stored MIDI channel and project PPQ/tempo, mapping each note's FL release value (0–128) to MIDI Note Off velocity (0–127). Stopping or finishing the preview sends All Notes Off; audio renders do not include MIDI output, and Pattern preview remains independent of Playlist playback. The opt-in **Send Playlist notes to MIDI output** setting schedules supported Pattern Clip notes against the audio frame position and arrangement tempo map, including per-note pan as MIDI CC 10 and Mod X/Mod Y as CC 74/CC 71; seek/resume restores notes that span the start position along with their active channel state. The separate **Send Pattern notes to MIDI output** setting loops the active Pattern's notes in PAT mode against the audio frame position and project tempo, restoring notes that span the loop phase after resume or reconnect. Pause, stop, disconnect, and completion send All Notes Off. Playlist note scheduling runs on a dedicated worker that follows audio transport frames, so UI stalls no longer delay note or controller messages; operating-system scheduling and MIDI driver latency still apply. The opt-in **Send MIDI clock with transport** setting runs on a dedicated scheduler that reads the audio transport frame position directly, follows the arrangement tempo map during Playlist playback and the project tempo in Pattern mode, and sends Start, Continue, Stop, and 24 clock ticks per quarter note. Pattern mode starts at the selected loop phase, including a Piano roll ruler seek, and preserves continuous clock timing across loop repeats. Resume and nonzero Playlist starts send a Song Position Pointer before Continue; UI stalls no longer delay clock pulses, though operating-system scheduling and MIDI driver latency still apply. It is off by default and should only be enabled for external hardware configured to receive MIDI sync. Per-channel Bank Select MSB/LSB and Program assignments (seven-bit values 0–127) persist in user settings and are sent before Program Change on connect, before the test note, and before nonempty Pattern or Playlist output. Bank Select MSB uses CC 0 and LSB uses CC 32. MIDI channel messages follow their assigned output port; unassigned channels use the selected default port, and MIDI clock and transport messages go to every connected output. Native project-stored MIDI Out bank/patch mapping and native controller timing remain incomplete ([Image-Line MIDI settings](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/envsettings_midi.htm), [MIDI Out plugin](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/plugins/MIDI%20Out.htm), [MIDI 1.0 Note Off message](https://midi.org/summary-of-midi-1-0-messages)).
- `[partial]` MIDI CC links can be learned for editable parameters in a loaded VST3 instrument's Parameters panel. Each link is scoped to the input device, MIDI channel, and controller, persists in user settings, and maps CC 0–127 linearly to the parameter's normalized range. A link applies only while the project channel still hosts the matching VST3 plug-in; Pattern event automation links and other plug-in formats remain incomplete.
- `[todo]` MIDI scripting API (FL uses Python `midi` module — device scripts)
- `[partial]` Controller templates: users can save learned output-gain and Play/Pause CC mappings as named reusable templates, apply them to a connected input, and delete templates. Built-in Channel 1 profiles map General MIDI CC 7 to output gain and CC 64 to Play/Pause, or CC 11 Expression to output gain. The Behringer X-TOUCH MINI Preset A and B profiles map their fader CC 9 and CC 10, respectively, on MIDI channel 11 to output gain. The X-TOUCH COMPACT Preset Layer A profile maps Fader 9's CC 9 on MIDI channel 1 to output gain. The Akai MIDImix profiles map the Master Fader's CC 62 and channel Faders 1–8 (CC 19, 23, 27, 31, 49, 53, 57, and 61) on MIDI channel 1 to output gain; knobs and buttons remain unmapped. Separately, MIDI Learn on a recognized Mixer strip maps input CCs, scoped by device and channel, to its saved fader, pan, stereo-separation, mute, phase-invert, left/right-swap, effect-chain enable, or insert solo control. Several strips and parameters can be mapped concurrently, with each device/channel/CC assigned to one control. Fader CC values span raw 0–16,000; pan CC 64 maps to center and CC 0/127 to raw −6,400/+6,400; stereo-separation CC 64 maps to 0 and CC 0/127 to raw −64/+64; mute, solo, phase-invert, left/right-swap, and effect-chain enable toggle on press values of 64 or higher and re-arm below 64. All update live playback, and continuous moves are grouped into one undo step; the pan and stereo-separation CC curves still need native comparison ([MIDI Association CC table](https://midi.org/midi-1-0-control-change-messages), [Behringer X-TOUCH MINI Quick Start Guide](https://mediadl.musictribe.com/media/PLM/data/docs/P0B3M/QSG_BE_0808-AAF_X-TOUCH-MINI_WW.pdf), [Behringer X-TOUCH COMPACT Quick Start Guide](https://mediadl.musictribe.com/media/sys_master/ha6/h2b/8849640980510.pdf), [Akai MIDImix User Guide](https://cdn.inmusicbrands.com/akai/attachments/MIDIMIX/MIDImix-UserGuide-v1.0.pdf), [Akai MIDImix Cubase mapping](https://support.akaipro.com/en/support/solutions/articles/69000837972-akai-pro-midimix-setup-with-steinberg-cubase)).

## 15. Desktop shell / UX

View > **Dock all and reset window positions** closes every detached editor and places saved windows in a visible cascade beside the main window, clamping oversized windows to monitor dimensions when available and otherwise to the main viewport dimensions. This recovers editors after a monitor layout changes. The shell uses eframe's WGPU renderer; the Windows project-open view was visually verified with a 96-clip ZENOLOGY project and nine VST3 channel states restored, and Linux Weston scaling was visually checked at 80%, 100%, and 140%. Automatic multi-monitor layout detection, Mac visual presentation, and further cross-platform scaling/control parity remain incomplete.
- `[partial]` Main menu: File, Edit, Add, Patterns, View, Options, Tools, and Help expose implemented project commands, editor switches, selected-pattern duplication via Alt/Option+C and the `duplicate-pattern` CLI command, Pattern renaming via the `rename-pattern` CLI command, guarded Pattern deletion, and a keyboard shortcut reference; remaining FL Studio menu commands are incomplete.
- `[partial]` Detached windows: the Playlist, Piano roll, Channel Rack, Mixer, Plug-ins, Audio settings, and Automation each open in a dedicated resizable native window and can be docked back from the View menu or main workspace. Positions and sizes persist between launches where supported; the recovery action docks all views and sets saved positions in a visible cascade beside the main window. Named window-layout presets save and restore the selected main view, Browser visibility, detached editor set, and valid editor positions and sizes across launches; presets can be replaced and deleted from the View menu. Automatic monitor detection remains incomplete. Audio settings scroll through their full control list in both main and detached views.
- `[partial]` Browser and transport toolbar: Files, Project, Plug-ins, Favorites, and Recent tabs with a persisted drag-resizable divider and persisted View/Alt/Option+F8 visibility toggle, plus transport, tempo, position, and pattern selection/creation. In PAT mode the toolbar position follows the active Pattern's loop phase, and the Piano roll draws a transport playhead for that Pattern. Clicking the Piano roll ruler seeks within the selected Pattern loop while PAT mode is stopped or playing; active Pattern playback loops enabled Sampler channels and loaded VST3 instruments, and can send the selected Pattern's note events to a connected MIDI output in sync with audio when enabled. Audio Clips and Mixer effects remain outside Pattern-mode playback. Image-Line documents the mode behavior and L shortcut in its [Toolbar manual](https://www.image-line.com/fl-studio-learning-content/fl-studio-online-manual/html/toolbar_panels.htm). The hint bar, project picker, detached layout, and remaining Browser controls are incomplete.
- `[partial]` Native two-finger scroll, pinch zoom, rotational vertical zoom, and two-finger tap zoom-to-fit are implemented inside the Playlist timeline and Piano roll note grid, following Image-Line's documented gestures ([Multi-touch Support](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/basics_interface.htm)); tap-to-fit uses current arrangement/pattern extents and respects editor zoom limits. - `[partial]` Themes / UI scaling: the Options menu can scale the interface from 80% to 140% and saves the choice locally; Linux virtual-display checks at 80%, 100%, and 140% keep the Browser, workspace, and status bar visible. Separate popup/menu and toolbar scales and Mac HiDPI verification remain.
- `[partial]` Keyboard shortcuts cover the main editors (F5, F6, F7, F9), Pattern rename and empty-Pattern navigation (F2, F4, Ctrl/Cmd+F4), project open (Ctrl/Cmd+O), Playlist mix render (Ctrl/Cmd+R), song MIDI export (Ctrl/Cmd+Shift+M), Piano roll MIDI import (Ctrl/Cmd+M), Space play/pause, L for PAT/SONG playback mode, recent projects (Alt/Option+1–0), save/undo/redo, and several Browser, Channel Rack, and Piano roll actions. - `[partial]` Undo/redo restores lossless FLP document snapshots across editors with a 64 MiB history cap and captures/restores loaded, mapped VST3 state for host-controlled edits; changes made directly in a plug-in's native editor and non-project UI state remain outside history
- `[partial]` Autosave and recovery: configurable 5/10/15-minute autosaves (or off) pause during playback; Frequent mode saves every five minutes during playback and before plug-in loading, while Very frequent mode saves every minute and before plug-in loading. Manual saves retain the prior project, a shared retention limit prunes old backups, startup/open offers recovery from a newer autosave, and File provides Backup now, Revert to last autosave, and numbered Save new version (Ctrl/Cmd+N). Opening another project or using File > Exit or the window close button with unsaved edits prompts to Save, Don't Save, or Cancel. Backup location and controls do not yet match FL Studio exactly.

## 17. Suggested milestone order

Ordered by dependency and by "most compatibility per unit effort":

1. **Format completion** — mixer state, automation events, all channel types
   (unlocks reading real-world projects fully)
2. **Audio engine bring-up (in progress)** — shared device capture/output,
   Windows WASAPI exclusive access, and one bounded Playlist stream that mixes
    audio clips, Sampler notes, and mapped VST3 instruments placed by Pattern
    Clips are implemented with provisional channel volume/pan. Matching
    installed VST3 channels now load on project open. Validate Playlist playback
    on each platform and compare timing, levels, and instrument behavior against
    native FL Studio output.
3. **Realtime sampler + scheduler (partial)** — selected-pattern and Playlist
   Sampler notes schedule at sample offsets with bounded polyphony, voice
   stealing, basic sample-rate conversion, and channel gain/pan. Pattern-mode
   transport now loops enabled Sampler and loaded VST3 channels together, and
   the Piano roll ruler can seek within the Pattern loop. VST3 instances retain
   processing state across loop boundaries; supported direct Mixer routing and
   PDC are applied, while Audio Clips and Mixer effects remain outside Pattern
   mode. Linear `TEMPO` automation now changes Playlist audio, Sampler, and VST3
   timing in the stream; envelopes and command queues remain.
4. **VST3 project-wide autoload + full plugin routing (partial)** — project
   opening now loads recognized channels when a matching installed VST3 is
   found and attempts supported marker-12 state restore. Broaden identity and
   state-layout support, add state write-back, then add automation, multibus
   routing, Mixer integration, process isolation, manual PDC, and compensation across effect/send routes.
5. **Full-song offline render (partial)** — Playlist audio, Samplers, and mapped
   VST3 instruments use the shared linear `TEMPO` map. Add parameter automation,
   Mixer routing/effects, manual and effect/send PDC, native comparison, and
   export options to complete the graph
6. **Mixer graph: PDC + sends/sidechain** — complete manual offsets, effect latency, and arbitrary route alignment
7. **Piano roll tools** — the editing depth users expect
8. **Playlist audio** — waveforms, fades, stretch
9. **Recording + Edison-class editor**
10. **MIDI hardware + export (partial)** — pattern and arrangement MIDI export now works for decoded layouts, including per-tick linear `TEMPO` automation on song export; native event values/duplicates, scaled clips, full note properties, and hardware support remain.
11. **Polish**: undo everywhere, themes, shortcuts, autosave

(Stock plugin DSP is intentionally absent from this list — see §4.)
