# FL Studio Full Parity & Compatibility Roadmap

What "done" means: open any `.flp` from any FL Studio version, play it back
sounding identical, edit it with the same tools, and save it back without data
loss. This document enumerates everything that requires, grouped by subsystem,
with the current status of this project against each item.

Status legend:

- `[done]` — implemented and working
- `[partial]` — started; works for a subset of cases
- `[todo]` — not started
- `[obsolete]` — removed from current FL Studio; not a current parity target
- `[not supported by FL Studio]` — no equivalent behavior exists in the native application

> Scope note: this covers the desktop DAW. FL Cloud, FL Studio Mobile, and
> online services are explicitly out of scope (see Non-goals).

## 2. Project model (in-memory representation)

The decoded document must model everything the format can express.

- `[partial]` Channels: summaries, sample paths, plugin state blobs, levels, known kind mapping, and Layer child relationships/raw flags
- `[partial]` Patterns: note lists per channel; empty patterns can be created when the project supplies an unambiguous note-event encoding, and Alt/Option+C or Patterns > Duplicate selected pattern copies the selected pattern's raw note-event payload plus recognized name and explicit length. Pattern-scoped time-signature markers are read, set, and deleted. Candidate `0xDF` 12-byte controller records are losslessly decoded, edited, duplicated from an existing raw template, deleted, and added/updated as snapped Draw or unsnapped Paint strokes through the API and Piano roll Events lane. Channel/flags meaning, target mapping, and native verification remain incomplete. Other unrecognized Pattern metadata stays opaque.
- `[partial]` Playlist: tracks, arrangements, clips with targets, and time markers that can be edited, created, and deleted through the API, CLI, and desktop editor
- `[partial]` Mixer: recognized insert summaries and parameter kinds, with exact-record value editing and insert-name editing; strips expose raw volume/pan controls for unique corpus-derived candidates. Automatic PDC covers supported direct-to-Master sources; paired Mixer sends now route supported playback/render sources through candidate paths and contribute to live insert meters; full-song offline renders also report supported pre-effect insert peaks. Destination mapping, send gain, Master-path verification, native meter-tap validation, effect processing, manual offsets, and effect-chain latency compensation remain incomplete
- `[partial]` Automation: type-5 channel point curves can be read and points in an existing blob edited, inserted, or removed from the desktop view; candidate Pattern `0xDF` event points can be edited, drawn, or painted without interpreting their target bytes. The linear `TEMPO` map drives song MIDI export and audio, Sampler, and VST3 timing in Playlist streaming and offline render. Native curve interpolation, parameter links, event target mapping, LFOs, and new clip creation remain incomplete
- `[partial]` Tempo automation: linear channel curves named `TEMPO` are sampled for song MIDI export and converted into a shared tick-to-frame map for Playlist audio, Sampler, and VST3 timing in live streaming and offline render. The 60–180 BPM value mapping and playback timing are inferred from the installed reference project and MIDI export; native render comparison, wider Automation Clip ranges, tension/easing, and LFO semantics remain
- `[partial]` Channel colors: the model, CLI, and Channel Rack read/write per-channel RGB values and sort by hue; the Channel Rack applies one color or a linear RGB gradient transactionally to selected channels, using the first and last selected row colors as gradient endpoints. Compact icons identify decoded channel kinds; instrument-specific native icons remain unsupported. Native instrument-specific icon mapping and comparison with FL Studio's native gradient behavior remain
- `[partial]` Swing / groove settings: reads and edits the project-level `0x0B` byte mix (0–128, default 0) and `0x61` word multiplier (0–128, default 128); Sampler pattern previews, Playlist Pattern Clips, and VST3 pattern render/preview shift aligned even-numbered 16th-step onsets by the combined global and source-channel mix. - `[partial]` Project settings: the project-wide time signature (`0x11`/`0x12`) is read and editable through the model, CLI, and desktop dialog; Playlist and Pattern signatures remain distinct. Stereo sources and native Mixer tracks still need comparison. Master pitch is read and editable in cents from the global signed-word `0x50` event; channel `0xC7` Enable main pitch and Add to Key states are read/editable through the model, CLI, and Channel Rack, and supported Sampler note playback/rendering and unstretched Playlist Audio Clips (scale unset or 1.0) apply the project pitch when enabled; Add to Key has no playback effect yet. Native instruments, stretched Audio Clips, VST3 routing, metronome, recording settings, and other project-wide settings remain incomplete
- `[partial]` Layer channels route notes to enabled Sampler and mapped VST3 children, including a stable per-note pseudo-random choice for Random. Native random sequencing, Sequential mode, velocity splits, Layer level/pan, and Crossfade remain incomplete

## 3. Audio engine

The hardest subsystem. See the difficulty discussion in chat history: this is
where real-time constraints punish sloppy code.

### 3.1 Device I/O

| Item | Status | Notes |
|---|---|---|
| Windows: WASAPI (shared + exclusive), DirectSound, ASIO | `[partial]` | Shared capture/output through CPAL and direct WASAPI exclusive streams are implemented, including endpoint selection, rate/buffer settings, input metering/monitoring, an output test tone, and one bounded Playlist stream that mixes audio clips, Sampler notes, and project-matched VST3 instruments on Pattern Clips using provisional volume/pan mapping. Opening a project now auto-loads channels whose VST3 identity matches an installed bundle; marker-12 state restoration is attempted, with unsupported state layouts reported while the loaded instance remains mapped for playback. ## 4. Native (stock) plugins

**Project decision (2026-10-06): stock plugin DSP is out of scope.** This
project will not reimplement Image-Line's instruments and effects. The
compatibility strategy for every stock plugin is a single one:

- **Host the original.** If the user has FL Studio (or the individual plugin)
  installed, load it like any other VST and restore its state from the FLP
  blob. A project opens and sounds right when the plugins are present;
  missing plugins are reported, not faked.

This removes the entire reimplementation surface (~110 plugins of proprietary
DSP: Sytrus, Harmor, FLEX, Gross Beat, Newtone, etc.). It also sidesteps the
legal risk of cloning trade-secret algorithms — hosting a plugin the user
legitimately owns is the standard DAW interop story.

What this still requires (tracked under §5, plugin hosting):

- Reliable VST2/VST3 state save/restore for Image-Line's own plugins, which
  use the same wrapper records as third-party plugins
- Graceful handling when a stock plugin isn't installed: show the channel,
  its settings blob size, and which plugin is missing — never silently drop
  the channel or corrupt the project
- `.fst` preset loading for Image-Line's native plugins and other VST wrapper
  layouts; format-32 channel-state presets now load into already hosted
  marker-12 VST3 channels when the class UID matches

No per-plugin DSP work is planned. If a stock plugin's state format ever needs
interpretation without the plugin present, that becomes a case-by-case
decision, not a roadmap item.

  merged mono, left-only, or right-only channels. The dialog also has
  0/1/2/5-second minimum tail presets and an optional finite VST3 tail extension
  capped at 60 seconds. Automatic PDC aligns supported direct-to-Master
  sources using loaded VST3 reports. Paired Mixer sends are applied to supported

  effect/send latency, native level comparison, and other export

  Mixer mute/solo/phase/swap flags are applied to supported sources as noted

- `[partial]` Formats: the desktop full-song Playlist, audio-clip, Sampler-pattern, and VST3-pattern renderers support WAV at 16/24-bit integer PCM or 32-bit float, FLAC at 16/24-bit integer, streamed Ogg Vorbis at a 64–450 kbps target average bitrate, and constant-bitrate MP3 at discrete rates from 32 to 320 kbps. All support stereo, merged mono, left-only, or right-only channels; MP3 output is limited to 32, 44.1, or 48 kHz. Full-song and VST3-pattern renders encode bounded blocks directly; audio-clip and Sampler-pattern renders first build a 512 MiB-capped mix buffer, then encode it in bounded blocks. FLAC records STREAMINFO length and PCM MD5, while OGG and MP3 use Vorbis ABR and LAME CBR encoding. OGG does not use the WAV PCM dither stage. MP3 export applies the selected TPDF or high-pass TPDF mode during 16-bit quantization before LAME encoding, as required for dithered MP3 output; its exact interaction with FL Studio's encoder remains unverified. Every WAV renderer supports Off, TPDF, or high-pass TPDF dither for 16-bit PCM, including Mixer stems; the high-pass mode uses a local first-order filter and still needs spectral comparison against FL Studio. VST3 pattern output accepts mono or stereo instrument buses ([Image-Line export manual](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/fformats_save_export.htm)).
- `[partial]` Render options: the Playlist mix dialog offers channel modes, 0/1/2/5-second base tails, optional finite VST3 instrument tail extension capped at 60 seconds (infinite reports use the selected base tail), Off/TPDF/high-pass TPDF dither for 16-bit WAV output and a selectable dither mode for MP3's 16-bit quantization stage, and Linear, 6-point Hermite, or 16/24/32/64/128/256/512-point windowed-sinc resampling, defaulting to 32-point sinc and retaining the selected quality between launches. Playlist WAV and Mixer stem renders can save arrangement time markers as RIFF cue points with associated labels; frame positions follow the arrangement tempo map, and the render extends through the last marker when needed. A separate Save note markers option writes cue points for Playlist Pattern note onsets and active Audio Clip starts. The high-pass TPDF option shifts most dither energy toward high frequencies with a local first-order filter; its exact spectrum is not yet compared with FL Studio, whose manual says its shaped dither places most noise above 10 kHz. Live playback offers Linear, 6-point Hermite, and 24/64/128/256/512-point sinc, defaulting to 24-point sinc as documented by Image-Line. Automatic “Leave remainder” tail rendering, exact MP3/FL Studio comparison, exact interpolation coefficients, and Mixer effect tail detection remain todo. Hermite remains a local six-sample quintic curve; sinc modes share a local variable-width Blackman-windowed kernel. These are not claims of bit-identical FL Studio output ([Image-Line export manual](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/fformats_save_export.htm), [Audio settings manual](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/envsettings_audio.htm), [Image-Line export quality discussion](https://forum.image-line.com/viewtopic.php?p=1886536)).
- `[partial]` Stem export: File > Render Mixer stems writes one WAV per enabled, recognized non-Master insert routed from a project channel and can optionally write `Master.wav` from the final supported mix plus `Current.wav` from a selected recognized, unmuted Mixer track's pre-effect bus. Master follows supported Master controls; each optional stem is omitted when muted or silent. The dialog uses the selected WAV depth, channel mode, and 16-bit dither mode, and can save Playlist or note markers with the same cue-point metadata as the main render. Mixer effects, automation, unknown route mapping, effect/send PDC, and FL Studio's "split channel tracks" mode remain incomplete ([Image-Line export manual](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/fformats_save_export.htm)).
- `[partial]` Selected Playlist clip render: File > Export can write one
  selected enabled audio-channel clip's supported sample source to WAV with the
  shared 16/24-bit PCM or 32-bit float depth, dither, and channel-mode settings,
  from either the clip start or its original song position, clipped to the
  Playlist endpoint. Looping or stretching clips beyond their source duration,
  Pattern Clip rendering, multiple selection, automatic Audio
  Clip insertion, source muting, automation, and Mixer effects remain
  incomplete. FL Studio's consolidation also accepts Pattern Clips and supports
  song-start placement with source muting ([Image-Line Playlist
  manual](https://www.image-line.com/fl-studio-learning-content/fl-studio-online-manual/html/playlist.htm)).
- `[partial]` Pattern render: the Piano roll can render enabled Sampler notes
  from the selected pattern to WAV with the shared bit depth, dither, and
  channel-mode settings, applying supported directly
  assigned insert mute/solo/phase/swap state and Master flags; a mapped VST3 channel can
  render its selected pattern notes to the selected WAV, FLAC, Ogg Vorbis, or
  MP3 format through the loaded instrument, using the shared render depth, dither,
  bitrate, and channel-mode settings. VST3 output buses must be mono or stereo.
  FL Studio renders selected patterns to audio clips with configurable render

  Patterns manual](https://www.image-line.com/fl-studio-learning-content/fl-studio-online-manual/html/menu_patterns.htm)).

## 14. MIDI hardware & scripting

- `[partial]` MIDI input: the Audio settings view can list, refresh, connect, and disconnect hardware inputs. The selected input port ID persists in user settings, but the hardware connection remains manual. The transport Record button's context menu independently enables Audio and Notes, persists these choices, and starts or stops both supported capture paths together; Automation is listed but unavailable. With Notes enabled, Record captures note-on/off events (including note-on velocity, release velocity, and MIDI channel) into the selected Pattern/channel. CC 10 pan, CC 74 Mod X, CC 71 Mod Y, and pitch bend are snapshotted at each Note On. Pan maps to FL's 0–128 note-pan range; Mod X/Y map MIDI 0–127 to FL 0–255 with center 64 at FL default 128; bend maps to FL's 10-cent fine-pitch steps using received RPN 0 sensitivity or the default ±2-semitone range. Later pan, Mod X/Y, and bend changes do not alter notes already captured. Incoming MIDI release velocity maps from 0–127 to FL's 0–128 note-release range, while notes still held at stop keep the default release value 64. The whole capture is one undoable project edit. Input quantization can be disabled or set to one-quarter beat, half beat, beat, two beats, or bar; enabled quantization rounds note starts and ends to the nearest grid. A persisted option can ignore incoming note-on velocity and record every note at fixed velocity 100; device velocity remains the default. A persisted -200 to +200 ms timing offset can move captured events earlier or later to compensate for system latency. When recording begins during Playlist playback inside a Pattern Clip for the selected Pattern, captured note positions are offset from that clip's start; otherwise notes start at Pattern tick zero. During continuous Playlist playback, note timing follows the active arrangement's linear `TEMPO` map; timestamps use host time, so device latency, pauses, or output underruns can still shift capture timing. During Playlist playback, stopping a take that began outside a clip of the selected Pattern adds a Pattern Clip at the captured start position on the first free track; the new clip spans at least one bar and expands to contain the Pattern's notes. Notes remain saved if no clip template or free track is available. Song-position timing across repeated clips and automatic clip resizing while recording remain incomplete. MIDI Start/Continue/Stop and MMC Play/Stop/Record commands operate the Playlist transport/recorder. Clock, song position, controller, pressure, and program messages are parsed for activity display; controller mapping/automation, live instrument audition, Automation recording, and MIDI scripting remain incomplete ([Image-Line MIDI settings](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/envsettings_midi.htm), [Note/MIDI recording](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/recording_scores.htm), [Piano roll scripting API](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/pianoroll_scripting_api.htm), [MIDI 1.0 Control Change Messages](https://midi.org/midi-1-0-control-change-messages)).
- `[partial]` MIDI input scale snapping: an optional setting moves recorded note pitches to the nearest note in the selected Piano roll scale, captured when the take begins. This supports scale-constrained note recording; live input audition and input snapping for sources other than recorded notes remain incomplete ([Image-Line Piano roll manual](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/pianoroll.htm)).
- `[partial]` MIDI output: Audio settings can enumerate, refresh, connect, and disconnect one external MIDI output interface. The selected output port ID and MIDI output options persist in user settings, but the hardware connection remains manual. Connect and disconnect send All Notes Off on all 16 channels; **Test C4** sends a short channel-1 note, and **Preview pattern** schedules valid notes from the selected Pattern using its stored MIDI channel and project PPQ/tempo, mapping each note's FL release value (0–128) to MIDI Note Off velocity (0–127). Stopping or finishing the preview sends All Notes Off; audio renders do not include MIDI output, and Pattern preview remains independent of Playlist playback. The opt-in **Send Playlist notes to MIDI output** setting schedules supported Pattern Clip notes against the audio frame position and arrangement tempo map, including per-note pan as MIDI CC 10 and Mod X/Mod Y as CC 74/CC 71; seek/resume restores notes that span the start position along with their active channel state. Pause, stop, disconnect, and completion send All Notes Off. The option defaults off, and UI-timer scheduling can jitter during long stalls. The opt-in **Send MIDI clock with transport** setting sends Start, Continue, Stop, and 24 clock ticks per quarter note while Playlist audio plays; resume and starts from a nonzero song position send a Song Position Pointer before Continue. It is off by default and should only be enabled for external hardware configured to receive MIDI sync. MIDI Out channel/patch configuration, per-channel port routing, and native controller timing remain incomplete ([Image-Line MIDI settings](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/envsettings_midi.htm), [MIDI Out plugin](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/plugins/MIDI%20Out.htm), [MIDI 1.0 Note Off message](https://midi.org/summary-of-midi-1-0-messages)).
- `[todo]` MIDI scripting API (FL uses Python `midi` module — device scripts)
- `[partial]` Controller templates: users can save learned output-gain and Play/Pause CC mappings as named reusable templates, apply them to a connected input, and delete templates. Built-in Channel 1 profiles map General MIDI CC 7 to output gain and CC 64 to Play/Pause, or CC 11 Expression to output gain. The Behringer X-TOUCH MINI Preset A and B profiles map their fader CC 9 and CC 10, respectively, on MIDI channel 11 to output gain. The X-TOUCH COMPACT Preset Layer A profile maps Fader 9's CC 9 on MIDI channel 1 to output gain. The Akai MIDImix profiles map the Master Fader's CC 62 and channel Faders 1–8 (CC 19, 23, 27, 31, 49, 53, 57, and 61) on MIDI channel 1 to output gain; knobs and buttons remain unmapped ([MIDI Association CC table](https://midi.org/midi-1-0-control-change-messages), [Behringer X-TOUCH MINI Quick Start Guide](https://mediadl.musictribe.com/media/PLM/data/docs/P0B3M/QSG_BE_0808-AAF_X-TOUCH-MINI_WW.pdf), [Behringer X-TOUCH COMPACT Quick Start Guide](https://mediadl.musictribe.com/media/sys_master/ha6/h2b/8849640980510.pdf), [Akai MIDImix User Guide](https://cdn.inmusicbrands.com/akai/attachments/MIDIMIX/MIDImix-UserGuide-v1.0.pdf), [Akai MIDImix Cubase mapping](https://support.akaipro.com/en/support/solutions/articles/69000837972-akai-pro-midimix-setup-with-steinberg-cubase)).

## 15. Desktop shell / UX

- `[partial]` Window management: Playlist, Channel Rack, Piano roll, Mixer, Plug-ins, Audio, and Automation views; F5–F9 shortcuts; and resizable native windows for all seven views. Detached editor positions and sizes persist where the platform reports geometry, and sizes persist on platforms that cannot report position. View > **Dock all and reset window positions** closes every detached editor and places saved windows in a visible cascade beside the main window, clamping oversized windows to monitor dimensions when available and otherwise to the main viewport dimensions. This recovers editors after a monitor layout changes. The shell uses eframe's WGPU renderer; the Windows project-open view was visually verified with a 96-clip ZENOLOGY project and nine VST3 channel states restored, and Linux Weston scaling was visually checked at 80%, 100%, and 140%. Automatic multi-monitor layout detection, Mac visual presentation, and further cross-platform scaling/control parity remain incomplete.
- `[partial]` Main menu: File, Edit, Add, Patterns, View, Options, Tools, and Help expose implemented project commands, editor switches, selected-pattern duplication via Alt/Option+C, and a keyboard shortcut reference; remaining FL Studio menu commands are incomplete.
- `[partial]` Detached windows: the Playlist, Piano roll, Channel Rack, Mixer, Plug-ins, Audio settings, and Automation each open in a dedicated resizable native window and can be docked back from the View menu or main workspace. All seven share app state, including the active project and undo/redo history, with the main window. Positions and sizes persist between launches where supported; the recovery action docks all views and sets saved positions in a visible cascade beside the main window. Named window-layout presets save and restore the selected main view, Browser visibility, detached editor set, and valid editor positions and sizes across launches; presets can be replaced and deleted from the View menu. Automatic monitor detection remains incomplete. Audio settings scroll through their full control list in both main and detached views.
- `[partial]` Browser and transport toolbar: Files, Project, Plug-ins, Favorites, and Recent tabs with a persisted drag-resizable divider and persisted View/Alt/Option+F8 visibility toggle, plus transport, tempo, position, and pattern selection/creation. The Browser starts at 280 points and keeps advanced search/filter controls collapsed until requested. Compact Browser/editor tab spacing and a width-aware Playlist zoom control keep the narrow toolbar groups distinct; the hint bar, project picker, PAT/SONG playback mode, detached layout, and remaining Browser controls are incomplete.
- `[partial]` Native two-finger scroll, pinch zoom, rotational vertical zoom, and two-finger tap zoom-to-fit are implemented inside the Playlist timeline and Piano roll note grid, following Image-Line's documented gestures ([Multi-touch Support](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/basics_interface.htm)); tap-to-fit uses current arrangement/pattern extents and respects editor zoom limits. One-finger touch uses the existing pointer editing behavior. Touch-sized controls and gesture support in other editors remain incomplete.
- `[partial]` Themes / UI scaling: the Options menu can scale the interface from 80% to 140% and saves the choice locally; Linux virtual-display checks at 80%, 100%, and 140% keep the Browser, workspace, and status bar visible. Separate popup/menu and toolbar scales and Mac HiDPI verification remain.
- `[partial]` Keyboard shortcuts cover the main editors (F5, F6, F7, F9), Space play/pause, recent projects (Alt/Option+1–0), save/undo/redo, and several Browser, Channel Rack, and Piano roll actions; the full FL Studio shortcut map remains incomplete.
- `[partial]` Undo/redo restores lossless FLP document snapshots across editors with a 64 MiB history cap and captures/restores loaded, mapped VST3 state for host-controlled edits; changes made directly in a plug-in's native editor and non-project UI state remain outside history
- `[partial]` Autosave and recovery: configurable 5/10/15-minute autosaves (or off) pause during playback; Frequent mode saves every five minutes during playback and before plug-in loading, while Very frequent mode saves every minute and before plug-in loading. Manual saves retain the prior project, a shared retention limit prunes old backups, startup/open offers recovery from a newer autosave, and File provides Backup now, Revert to last autosave, and numbered Save new version (Ctrl/Cmd+N). Opening another project or using File > Exit or the window close button with unsaved edits prompts to Save, Don't Save, or Cancel. Untitled projects cannot autosave, and backup location/controls do not yet match FL Studio exactly.

## 17. Suggested milestone order

Ordered by dependency and by "most compatibility per unit effort":

1. **Format completion** — mixer state, automation events, all channel types
   (unlocks reading real-world projects fully)
2. **Audio engine bring-up (in progress)** — shared device capture/output,
   Windows WASAPI exclusive access, and one bounded Playlist stream that mixes
    audio clips, Sampler notes, and mapped VST3 instruments placed by Pattern
    Clips are implemented with provisional channel volume/pan. Matching
    installed VST3 channels now load on project open. Validate Playlist playback
    on each platform and compare timing, levels, and instrument behavior against
    native FL Studio output.
3. **Realtime sampler + scheduler (partial)** — selected-pattern and Playlist
   Sampler notes schedule at sample offsets with bounded polyphony, voice
   stealing, basic sample-rate conversion, and channel gain/pan. VST3 Pattern
   Clip transport now runs for mapped VST3 instances. Linear `TEMPO` automation
   now changes Playlist audio, Sampler, and VST3 timing in the stream; transport
   seek/display, envelopes, and command queues remain.
4. **VST3 project-wide autoload + full plugin routing (partial)** — project
   opening now loads recognized channels when a matching installed VST3 is
   found and attempts supported marker-12 state restore. Broaden identity and
   state-layout support, add state write-back, then add automation, multibus
   routing, Mixer integration, process isolation, manual PDC, and compensation across effect/send routes.
5. **Full-song offline render (partial)** — Playlist audio, Samplers, and mapped
   VST3 instruments use the shared linear `TEMPO` map. Add parameter automation,
   Mixer routing/effects, manual and effect/send PDC, native comparison, and
   export options to complete the graph
6. **Mixer graph: PDC + sends/sidechain** — complete manual offsets, effect latency, and arbitrary route alignment
7. **Piano roll tools** — the editing depth users expect
8. **Playlist audio** — waveforms, fades, stretch
9. **Recording + Edison-class editor**
10. **MIDI hardware + export (partial)** — pattern and arrangement MIDI export now works for decoded layouts, including per-tick linear `TEMPO` automation on song export; native event values/duplicates, scaled clips, full note properties, and hardware support remain.
11. **Polish**: undo everywhere, themes, shortcuts, autosave

(Stock plugin DSP is intentionally absent from this list — see §4.)
