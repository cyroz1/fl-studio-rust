# FL Studio Full Parity & Compatibility Roadmap

What "done" means: open any `.flp` from any FL Studio version, play it back
sounding identical, edit it with the same tools, and save it back without data
loss. This document enumerates everything that requires, grouped by subsystem,
with the current status of this project against each item.

Status legend:

- `[done]` — implemented and working
- `[partial]` — started; works for a subset of cases
- `[todo]` — not started
- `[obsolete]` — removed from current FL Studio; not a current parity target
- `[not supported by FL Studio]` — no equivalent behavior exists in the native application

> Scope note: this covers the desktop DAW. FL Cloud, FL Studio Mobile, and
> online services are explicitly out of scope (see Non-goals).

---

## 1. File format compatibility

The foundation. Everything else depends on reading projects exactly.

| Header fields: PPQ, tempo, time signature, project metadata | `[partial]` | Tempo, the project-wide time signature, build number, and Project Info strings are decoded. The project signature is editable in Project Settings and through the CLI; Pattern and Playlist signatures are separately scoped and editable in the Piano roll, Playlist, and CLI. Project Master pitch is read from the global signed-word `0x50` event and can be edited through Project settings, the API, and CLI. Channel Parameters `0xC7` byte 12 stores Enable main pitch and byte 64 stores Add to Key; both are read/editable through the API, Channel Rack, and CLI. | Project Info: title, author, comments, genre, web link | `[done]` | Read/write through the desktop Project Info dialog and CLI. Metadata events are edited without rewriting unrelated event bytes. |
| Sampler Envelope/LFO records (`0xDA`) | `[partial]` | All five ordered targets (Panning, Volume, Mod X, Mod Y, Pitch) decode their recognized envelope and LFO raw fields and can be edited through the API, CLI, and Channel Rack while preserving unknown flag bits and trailing bytes. Field mappings and ranges follow a pinned third-party PyFLP parser and still need controlled FL Studio save verification. Sampler playback applies the enabled Volume envelope's pre-delay, attack, hold, decay, sustain, and release with a linear curve and saved signed Amount when its fields are valid. The raw-time conversion is a candidate calculated but unused by a public FLP parser; its mapping, the linear curves, and the Amount behavior need controlled FL Studio save/render comparison. Tempo-synced timing and attack/decay/release tension curves remain unsupported, as do other Envelope/LFO targets. |
| Channel records: all types (sampler, generator, layer, MIDI out, automation clip) | `[partial]` | Known channel kind values 0/1/2/3/4/5 are named while unknown raw values are retained; `0x00` enabled state is decoded and can be toggled through the CLI and Channel Rack by editing the existing event or inserting it after `0x15`, preserving unrelated channel events. `0x0F` compact state is decoded and editable through the API, CLI, and UI while preserving unrelated channel events; `set-channel-zipped` inserts the event after the channel kind when needed. The signed-byte Mixer track assignment (`0x16`) is decoded and used for stable Mixer-track sorting, with generator and Layer channels first. Each channel can also be routed to Current, Master, or insert 1–127 through the API, CLI, and Channel Rack context menu, with multi-channel UI edits applied atomically. Kind-0 Sampler, kind-1 MIDI Out, kind-2 Native instrument, kind-3 Layer, kind-4 Audio Clip, and kind-5 Automation channels can also be duplicated from the Channel Rack or CLI, preserving their channel events and Automation point bytes while assigning a new ID and display name; Layer clones retain their saved child references and flags, Audio Clip clones retain their sample path and saved settings without retargeting existing Playlist clips, and MIDI Out clones retain their saved MIDI routing. Unknown channel kinds remain unsupported ([MIDI Out controls](https://ww2.image-line.com/fl-studio-learning/fl-studio-online-manual/html/plugins/MIDI%20Out.htm)). The CLI exposes per-channel movement and sorting by color, Mixer track, name, or type. Display group names (`0xE7`) and signed group numbers (`0x91`) are decoded; All, Unsorted, and named groups can be filtered, selected channels can be assigned to an existing or newly created group, and groups can be added empty, renamed, and deleted while unassigning their channels and reindexing later groups. Muted state is honored by supported Sampler, audio-channel, and loaded VST3 song playback/rendering. `0x80` channel colors are decoded and can be edited from the Channel Rack or CLI, applied transactionally as a common color or linear RGB gradient across selected Channel Rack rows, and sorted by hue; each channel's fourth byte is retained. `0xC4` sample paths are decoded for kind-0 Sampler and kind-4 sample-backed channels; existing paths can be edited through the API, CLI, or Channel Rack while preserving the project string encoding; the API and CLI can create either channel type with the next available ID while using the project string encoding; Layer child IDs (`0x5E`) and raw flags (`0x90`) are decoded, and child lists can be edited in the Channel Rack through named channel choices while preserving other channel events. Sampler precomputed Fade Out (`0x4B`) and Fade In (`0x4C`) values are read from their word events and editable through the API, CLI, and Channel Rack in the documented 0–1024 range; missing values are inserted beside existing Sampler FX controls, and unrelated events are retained. Image-Line describes these as precomputed sample processing, and an Image-Line forum explanation describes Fade In attenuation at the sample start and Fade Out attenuation at the end across the sample. Supported Sampler playback and renders use raw/1024 as attenuation at the corresponding endpoint, with a provisional linear-amplitude taper across sample data; the exact native curve and loop interaction remain open ([Sampler Channel manual](https://www.image-line.com/fl-studio-learning-content/fl-studio-online-manual/html/chansettings_sampler.htm), [PyFLP event layout](https://pyflp.readthedocs.io/en/stable/reference/events.html), [Image-Line forum discussion](https://forum.image-line.com/viewtopic.php?t=151347)). The observed Random and Crossfade bits can be edited in the API, CLI, and Channel Rack without changing other flag bits; the Layer Fade value can be edited from 0–256 through the API, CLI, and Channel Rack while retaining the remaining Parameters bytes. Pattern notes on Layers recursively route to enabled Sampler and mapped VST3 descendants; each nested Layer applies its own key region and Random choice, using stable per-note pseudo-random selection. Sampler routes also apply nested Layer volume and pan Level Adjusts using provisional raw mappings. Saved inclusive key regions from channel Parameters events (`0xC7`) filter source notes and children before selection. When both bounds exist in one recognized Parameters payload, the API, `set-channel-key-region` CLI command, and Channel Rack can edit them while preserving the remaining event bytes. The model and `channels` command expose raw pan, volume, unknown, Mod X, and Mod Y fields from recognized channel `0xD5` Level Adjusts payloads. The API and `edit-channel-level-adjustments` CLI command can edit established fields in one event selected by its global event index while preserving the unknown field, trailing bytes, length prefix, and unrelated events; plug-in-tagged channels and recognized VST envelopes are rejected to avoid treating plug-in state as level data. For a unique recognized `0xD5` record on a Layer, supported Sampler routes apply volume raw `0..=12800` as provisional linear gain (`raw / 10,000`) and pan raw `-6,400..=6,400` as an additive pan offset, composing through nested Layers. Invalid ranges and duplicate Level Adjusts records are ignored; Mod X/Mod Y remain unapplied. VST3 descendants apply Layer gain and pan through the standard Volume/Pan note-expression dimensions only when the plug-in advertises each dimension. The provisional Volume mapping sends `max(gain, 0) / 4`, clamped to `0..=1`, and the Pan mapping adds the Layer raw offset divided by 12,800 to normalized note pan, clamped to `0..=1`; these mappings still need native comparison and plug-in behavior can vary ([Steinberg VST3 Note Expression types](https://steinbergmedia.github.io/vst3_doc/vstinterfaces/namespaceSteinberg_1_1Vst.html)). Image-Line documents that Layer adjustments affect only notes played through that Layer ([Layer manual](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/chansettings_layer.htm)); the raw mappings still need native save/render comparison. Layer Crossfade reads the saved `0xC7` Fade value (offset 88, range 0–256) and applies linear gains between adjacent active child subtrees when every leaf is an enabled, key-matching Sampler; nested Sampler-only Layers compose their gains during Pattern preview, Playlist playback, and supported renders. VST3-only subtrees also crossfade in VST3 Pattern mixes, Pattern-loop playback, Playlist/Performance streams, and live MIDI audition when every active leaf is a loaded VST3 channel whose plug-in advertises Volume note expression. Mixed Sampler/VST3 subtrees crossfade in combined Playlist/Performance playback and full-song/stem renders when every active leaf is an enabled, key-matching Sampler or a loaded VST3 channel with Volume note expression. Mixed Sampler/VST3 subtrees also crossfade in one-shot Pattern preview, Pattern-loop playback, and live MIDI audition using the same routing decision when every active leaf is eligible; trees containing unsupported leaves retain normal routing. The fade curve still needs native comparison. Native Random sequencing and Sequential mode remain incomplete; no saved Sequential field has been confirmed, so unknown flag bits remain untouched. Image-Line documents native Layer key regions but no per-child velocity zones; FPC velocity ranges belong to FPC's plugin state, not generic Layer routing ([Layer Settings](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/chansettings_layer.htm), [FPC velocity ranges](https://www.image-line.com/fl-studio-learning-content/fl-studio-online-manual/html/plugins/FPC.htm)). Legacy channel types remain incomplete. Sampler descendants use the provisional mappings described above, and VST3 descendants apply Layer gain/pan only through advertised standard note-expression dimensions. ([Image-Line key-region behavior](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/chansettings_misc.htm), [PyFLP Parameters layout](https://github.com/demberto/PyFLP/blob/master/pyflp/channel.py), [PyFLP Level Adjusts layout](https://pyflp.readthedocs.io/en/latest/_modules/pyflp/channel.html)). |

Operations retain reserved/channel/flags bytes. The lane filters by raw channel/flags without interpreting them. Native target mapping and scale behavior, curve parity, native save verification, and other Pattern metadata remain incomplete. |

### 3.2 Real-time thread

- `[partial]` Lock-free audio callback: shared CPAL callbacks avoid allocation and locks; replaced project/Browser sample buffers and input/processed-monitor recording rings are retained while realtime readers hold their ArcSwap guards, so device callbacks cannot release their last reference. Engine-owned output and capture buffers are reaped from the control thread. The WASAPI exclusive output worker preallocates for the initialized device buffer size and rejects any later event requesting more frames, keeping its byte buffer from growing during playback
- `[partial]` Lock-free command queue (UI thread → audio thread): the shared output callback and Windows exclusive output loop drain a bounded lock-free queue of transport source changes and Browser preview gain updates. The queue keeps the newest state if it fills. Sampler live MIDI note and controller events now use a separate 1,024-entry bounded lock-free queue to the Sampler render worker; on overflow, the worker discards pending events, stops live voices, and resets sustain, sostenuto, pitch, pan, volume, and expression to avoid stuck notes. Stopped-transport VST3 live MIDI uses a separate 1,024-entry bounded lock-free queue; overflow ends the audition session, whose worker releases active VST3 notes before stopping. Mixed Layer Sampler/VST3 live MIDI also uses a 1,024-entry bounded lock-free queue; overflow stops the audition, releases active VST3 notes, and ends the Sampler renderer. Project stream instances removed by stop or staged cancellation enter the bounded retirement queue, with a control-thread overflow list; a callback reader counter and handoff gate keep the UI reaper from releasing them before active output readers leave. Direct pause/stop flags remain, and Pattern transport note scheduling stays outside the AudioEngine command queue.
- `[partial]` Lock-free metering/state queue (audio thread → UI thread): input peak and callback frame counts are published through atomic values; device stream errors use a 64-entry bounded lock-free event queue that the UI drains into its bounded history and latest-error status. ## 4. Native (stock) plugins

**Project decision (2026-10-06): stock plugin DSP is out of scope.** This
project will not reimplement Image-Line's instruments and effects. The
compatibility strategy for every stock plugin is a single one:

- **Host the original.** If the user has FL Studio (or the individual plugin)
  installed, load it like any other VST and restore its state from the FLP
  blob. A project opens and sounds right when the plugins are present;
  missing plugins are reported, not faked.

This removes the entire reimplementation surface (~110 plugins of proprietary
DSP: Sytrus, Harmor, FLEX, Gross Beat, Newtone, etc.). It also sidesteps the
legal risk of cloning trade-secret algorithms — hosting a plugin the user
legitimately owns is the standard DAW interop story.

What this still requires (tracked under §5, plugin hosting):

- Reliable VST2/VST3 state save/restore for Image-Line's own plugins, which
  use the same wrapper records as third-party plugins
- Graceful handling when a stock plugin isn't installed: show the channel,
  its settings blob size, and which plugin is missing — never silently drop
  the channel or corrupt the project
- `.fst` preset loading for Image-Line's native plugins and other VST wrapper
  layouts; format-32 channel-state presets now load into already hosted
  marker-12 VST3 channels when the class UID matches

No per-plugin DSP work is planned. If a stock plugin's state format ever needs
interpretation without the plugin present, that becomes a case-by-case
decision, not a roadmap item.

Current: experimental offline renders include audio clips, Sampler Pattern
Clips, and mapped VST3 instruments in one bounded Playlist mix to WAV, FLAC,
OGG, or MP3. The desktop dialog can choose 16/24-bit integer PCM or 32-bit
float WAV, 16/24-bit integer FLAC, Ogg Vorbis at a target average bitrate, or
MP3 at a constant bitrate from 32 to 320 kbps. All four formats support stereo
or mono channel modes; MP3 output is limited to 32, 44.1, or 48 kHz. Renders can append up to five
seconds after the final scheduled clip, and 16-bit PCM WAV can apply TPDF or
high-pass TPDF dither. This first combined renderer uses base tempo and provisional channel
volume/pan; it applies automatic PDC using loaded VST3 instrument and Mixer effect reports across supported direct-to-Master and saved send routes with provisional destination/gain mappings. Automation and live behavior for unsupported Mixer routes remain incomplete. Manual offsets and native auxiliary-bus mapping still need verification; loaded VST3 effects with active auxiliary inputs receive routed sources, including zero-level sidechain-only routes, with those feeds included in PDC; loaded VST3 effects process on known inserts before their fader/pan/send transforms, with Master slots before Master output controls.
Supported Master flags and directly routed insert mute/solo/phase/swap state
are applied where the Mixer rows below describe. Full export surface:

## 14. MIDI hardware & scripting

- `[partial]` MIDI input: the Audio settings view can list, refresh, connect, and disconnect hardware inputs. The selected input port ID persists in user settings, and an optional startup setting reconnects it when available; without that setting, the hardware connection remains manual. The transport Record button's context menu independently enables Audio, Notes, and CC automation, persists these choices, and starts or stops the enabled capture paths together. By default, CC automation records one configured controller number into the selected Pattern's raw `0xDF` stream, using the configured stream channel and flags; values are normalized to 0–1 and repeated points at the same tick coalesce to the latest value. A persisted Playlist Automation target, available during Playlist playback, instead creates a new Automation Clip by duplicating the selected type-5 channel and replacing its curve with the take. It starts at the captured song position on the selected Playlist track, falling back to the source channel's track, and lasts at least one bar; tick positions follow the active Playlist tempo map and recording offset. Existing app-local VST3 parameter links are copied to the new channel. This mode requires a selected type-5 channel with a recognized point blob and an existing Automation Clip record template. CC automation can be recorded with or without Notes. With Notes enabled, Record captures note-on/off events (including note-on velocity, release velocity, and MIDI channel) into the selected Pattern/channel; CC64 sustain defers captured note-offs independently per MIDI channel until pedal-up, CC121, or recording stop; CC66 sostenuto captures only notes active at pedal-down. When both pedals hold a note, it ends after the last pedal-up while retaining note-off release velocity. CC120 closes active and sustained notes on its input channel immediately; CC123–127 act as note-offs and respect sustain and sostenuto. CC 10 pan, CC 74 Mod X, CC 71 Mod Y, and pitch bend are snapshotted at each Note On. Pan maps to FL's 0–128 note-pan range; Mod X/Y map MIDI 0–127 to FL 0–255 with center 64 at FL default 128; bend maps to FL's 10-cent fine-pitch steps using received RPN 0 sensitivity or the default ±2-semitone range; selecting an NRPN prevents its data-entry messages from changing the remembered RPN bend range. Live note recording also snapshots RPN channel coarse and fine tuning, combining them with bend and preserving the source key when the FL fine-pitch range permits; larger offsets may change the recorded key, and out-of-range offsets are clamped. Later pan, Mod X/Y, bend, and tuning changes do not alter notes already captured. Live Sampler and Sampler Layer audition apply channel tuning and full pitch bend to sounding voices and initialize from current input state; VST3 audition forwards tuning RPN messages and restores current values at session start for plug-ins that handle them. Incoming MIDI release velocity maps from 0–127 to FL's 0–128 note-release range, while notes still held at stop keep the default release value 64. The whole capture is one undoable project edit. Input quantization can be disabled or set to quarter-beat, half-beat, beat, two-beat, or bar grids, or to 1/16, 1/8, 1/4, or 1/2 triplet grids; enabled quantization rounds note starts and ends to the nearest grid. A persisted option can ignore incoming note-on velocity and record every note at fixed velocity 100; device velocity remains the default. A persisted -200 to +200 ms timing offset can move captured events earlier or later to compensate for system latency. When recording begins during Playlist playback inside a Pattern Clip for the selected Pattern, captured note positions are offset from that clip's start; otherwise notes start at Pattern tick zero. During continuous Playlist playback, note timing follows the active arrangement's linear `TEMPO` map; timestamps use host time, so device latency, pauses, or output underruns can still shift capture timing. During Playlist playback, stopping a take that began outside a clip of the selected Pattern adds a Pattern Clip at the captured start position on the first free track; the new clip spans at least one bar and expands to contain the Pattern's notes. A take that starts inside an existing Pattern Clip extends that clip to include the captured notes when its source window is safely resizable. Notes remain saved if no clip template or free track is available. During Playlist capture, MIDI note and selected-CC positions inside matching default-scale Pattern Clips map into the Pattern loop when their source window is full-source or a recognized FL Studio 2026 tick window whose span matches the clip length; explicit source-start offsets are applied, repeated clips record onto corresponding source ticks, and note durations remain continuous across loop boundaries. Recognized one-to-one 88-byte windows with nonzero source starts can be right-resized and split where the source tick reaches a Pattern repeat boundary; clip extension uses the Playlist ticks elapsed from the take start inside the clip and the source-offset-aware extent of captured notes. Scaled clips, source windows whose tick span differs from the clip length, legacy non-default or unrecognized source windows, resizing or extending clips with mismatched or unrecognized source windows, and native recording timing comparison remain incomplete. Native recording timing still needs comparison. MIDI Start/Continue/Stop and MMC Play/Stop/Record commands operate the Playlist transport/recorder. Clock, song position, controller, pressure, and program messages are parsed for activity display and can be forwarded by MIDI Thru. When transport is stopped, incoming note-on/off events audition the selected Pattern’s enabled Sampler channel through a low-latency stream; the project must be saved so its sample paths resolve. A directly selected loaded VST3 channel can also be auditioned through a low-latency VST3 stream, which applies the channel’s saved key region and preserves note-off pairing for suppressed notes. A selected Layer can route live notes through its key regions and Random selection when its enabled descendants resolve to loaded VST3 channels, Samplers with resolvable saved-project sample paths, or a mix of both; nested Layers recurse through their child key regions and Random selection. Mixed Sampler audio is aligned to VST3 latency, and both destinations share the Layer’s note routing and controller input; Layer-routed Sampler voices apply CC 7/39 Channel Volume, CC 10/42 Pan, and CC 11/43 Expression to new and already sounding voices per input channel. Each pair retains the existing 7-bit MSB mapping until its corresponding LSB arrives, then the Sampler uses the combined 14-bit value; these gain and pan mappings still need native comparison. The MIDI input scale-snap preference applies to all these destinations, and note-offs retain the mapped key if the setting changes while held. Direct Sampler live audition applies CC 7/39 Channel Volume, CC 10/42 Pan, and CC 11/43 Expression to new and already sounding voices per input channel, using each 7-bit MSB mapping until its corresponding LSB arrives and the combined 14-bit mapping afterward; CC 120 immediately silences that channel’s voices, and CC 123–127 release its live notes while respecting sustain. CC 121 resets pan to center, CC 7/11 to 127, and pitch bend to center while retaining RPN bend range and tuning and clearing parameter selection, following [Roland’s documented receiver behavior](https://cdn.roland.com/assets/media/pdf/M-GS64_OM.pdf); the linear gain law and reset values still need native FL Studio comparison. Live loaded VST3 audition forwards incoming Control Change, Program Change, pitch bend, and channel/polyphonic aftertouch messages to the selected channel or its routed VST3 children, and synchronizes tracked channel volume, pan, expression, modulation, sustain, and bend state when audition starts. During Playlist playback, direct Sampler input overlays live audio and loaded VST3 input reaches an active Playlist processor; Pattern playback overlays Sampler input and routes VST3 input through the active Pattern stream. During Playlist, Pattern, and Performance playback, a selected Layer routes each note through its saved and nested key regions and Random selection to the matching live Sampler overlay and active VST3 processors; VST3 targets apply Layer gain/pan through advertised standard note-expression dimensions and retain the note ID through note-off. Mixed Layer notes share the same Random choice and mapped note-off. Performance Mode reserves its configured MIDI channel (default channel 1) for clip and scene controls; other channels audition the selected Sampler, loaded VST3, or supported Layer through the active Performance stream. Recording other control sources into Automation Clips, broader controller mapping, and MIDI scripting remain incomplete ([Image-Line MIDI settings](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/envsettings_midi.htm), [Note/MIDI recording](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/recording_scores.htm), [Piano roll scripting API](https://www.image-line.com/fl-studio-learning/fl-studio-online-manual/html/pianoroll_scripting_api.htm), [MIDI 1.0 Control Change Messages](https://midi.org/midi-1-0-control-change-messages)).

- `[partial]` MIDI Thru: Audio settings can forward incoming notes, controllers, pitch bend, clock, song position, and Start/Continue/Stop messages to the selected external MIDI output while both devices are connected. - `[partial]` Autosave and recovery: configurable 5/10/15-minute autosaves (or off) pause during playback; Frequent mode saves every five minutes during playback and before plug-in loading, while Very frequent mode saves every minute and before plug-in loading. Manual saves retain the prior project, a shared retention limit prunes old backups, startup/open offers recovery from a newer autosave, and File provides Backup now, Revert to last autosave, and numbered Save new version (Ctrl/Cmd+N). Untitled projects also autosave and offer startup recovery while retaining their template path. Opening another project or using File > Exit or the window close button with unsaved edits prompts to Save, Don't Save, or Cancel. Backup location and controls do not yet match FL Studio exactly.

## 17. Suggested milestone order

Ordered by dependency and by "most compatibility per unit effort":

1. **Format completion** — mixer state, automation events, all channel types
   (unlocks reading real-world projects fully)
2. **Audio engine bring-up (in progress)** — shared device capture/output,
   Windows WASAPI exclusive access, and one bounded Playlist stream that mixes
    audio clips, Sampler notes, and mapped VST3 instruments placed by Pattern
    Clips are implemented with provisional channel volume/pan. Matching
    installed VST3 channels now load on project open. Validate Playlist playback
    on each platform and compare timing, levels, and instrument behavior against
    native FL Studio output.
3. **Realtime sampler + scheduler (partial)** — selected-pattern and Playlist
   Sampler notes schedule at sample offsets with bounded polyphony, voice
   stealing, basic sample-rate conversion, and channel gain/pan. Pattern-mode
   transport now loops enabled Sampler and loaded VST3 channels together, and
   the Piano roll ruler can seek within the Pattern loop. VST3 instances retain
   processing state across loop boundaries; supported direct Mixer routing and
   PDC are applied, and loaded effects on known Mixer inserts process in saved order using dedicated pre-effect
   input buses. Audio Clips remain outside Pattern mode. Linear `TEMPO` automation now changes Playlist audio, Sampler, and VST3
   timing in the stream; envelopes and command queues remain.
4. **VST3 project-wide autoload + full plugin routing (partial)** — project
   opening now loads recognized channels when a matching installed VST3 is
   found and attempts supported marker-12 state restore. Broaden identity and
   state-layout support and broader state write-back; extend native project-stored automation and LFO links to remaining targets,
   multibus routing, manual PDC, native sidechain-bus mapping validation, and native route validation.
5. **Full-song offline render (partial)** — Playlist audio, Samplers, and mapped
   VST3 instruments use the shared linear `TEMPO` map. Extend automation beyond app-local Pattern Event/LFO links and linked type-5 Clips to native project-stored sources and unsupported Mixer routes; add manual PDC, verify native sidechain-bus mapping,
   and add native comparison and export options to complete the graph
6. **Mixer graph: PDC + sends/sidechain** — embed native project-stored manual offsets in FLP files (app-local instance overrides are supported), support routed sidechain audio on active auxiliary inputs of loaded VST3 effects, then verify native bus mapping and arbitrary route alignment; live Song, Pattern-loop, and Performance PDC updates now apply at audio-block boundaries
7. **Piano roll tools** — the editing depth users expect
8. **Playlist audio** — waveforms, fades, stretch
9. **Recording + Edison-class editor**
10. **MIDI hardware + export (partial)** — pattern and arrangement MIDI export now works for decoded layouts, including per-tick linear `TEMPO` automation on song export; native event values/duplicates, scaled clips, full note properties, and hardware support remain.
11. **Polish**: undo everywhere, themes, shortcuts, autosave
